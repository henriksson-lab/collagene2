# Saved digest origins in cloning controls

The source-origin picker discovers exact saved run products and saved digest
fragment events. Selecting one retains a bounded documentary reconstruction
recipe; each downstream native operation replays it before obtaining material.
Renamed digest descendants and repeated digestion of a digest-origin document
are currently explicitly unsupported in the virtual-digest inspector.

A digest of an actual saved run product can open its chosen fragment through the
same cancellable, fingerprint-guarded atomic workspace installation as an ordinary
catalog digest. The native digest derivation record remains attached. The opened
document can be selected for ordinary PCR or assembly; assembly emits
`FromDigest` with the requested preparation rather than substituting its reference
sequence as stock. Ordinary PCR retains origin findings as documentary output,
without inventing an independent target or a verified run.

Assembly draft version 12 carries digest origins. Legacy run capsules retain their
original bare encoding and versions 1–11 remain readable. A digest origin cannot
be stored under an older draft version; unknown version 13 is rejected. Existing
run-only advanced panels reject derived digest origins before dispatch, leaving
the selection visible rather than silently discarding it.

Source formatting and native fixtures are prepared without browser checks. The
parent native/WASM batch provides compiler and fixture validation.
