# Native runs and saved digest fragment origins

`run_material::MaterialSelection` names either a retained run product selection or an exact saved digest product event. `MaterialOrigin` carries the corresponding closed native recipe capsule. These serialized declarations are documentary instructions, never duplex authority. Existing run-only inspection jobs and capsule layouts remain unchanged.

`inspect_material` discovers choices for one exact saved event. An explicit choice is freshly reconstructed before returning an executable capsule; failure remains a visible finding with no selected origin. Run products retain the existing proven name-only ancestry rules. Digest choices initially require the exact recorded product event; renamed or equal-DNA aliases are not inferred. `MaterialOrigin::validate_for_workspace` checks retained native ownership, exact source snapshots, source events, targets and derivation records without granting physical state.

The native verifier’s appended `ReconstructDigestFragment` operation must consume a named `Source::Input`. Its saved input binding must exactly equal the capsule record’s product binding. Fresh replay reconstructs the originating native run, performs the catalog-pinned actual digest and selects the declared actual fragment, preserving strand offsets, termini, nicks and positional modifications. `FreshFragment::into_parts` moves that in-process state and the bounded incomplete-origin findings into the verifier. No independent target is invented for the digest operation; the enclosing cloning plan has its own independent target.

The common iterative traversal in `run_material_capsule` visits both run and digest layers. Digest derivations consume an ancestry level rather than hiding their source run below a fresh allowance. Every root and descendant shares the existing eight-generation, 8 MiB aggregate capsule-byte, eight-million input-base, 1000-step and 1000-input bounds, plus rich-model bounds. Digest serialized wrappers and decoded native candidate bytes are both charged conservatively, reflecting their simultaneous retained representations. Charge checks precede decoding the corresponding native candidate; source/model checks precede its identity hashes. There is no per-child recursive budget reset. Workspace attestation first checks the full declaration under these limits, then compares its nodes against retained records. Historic documentary scientific-engine contexts remain readable; current source reconstruction is still required for material reuse.

Compilers use borrowed `MaterialOriginRef::{Run,Digest}` with `material_capsules_preflight` before copying source capsules. Worker capability checks use `visit_candidate_plans` to inspect all native plans through mixed layers with the same traversal and limits. Native plan schema 19 is required for digest reconstruction; older plan schemas remain readable for their established operations. The parent protocol layer owns candidate and worker floors.

`mixed_origins.rs` specifies a literal original PCR, EcoRI sticky digest and a second PCR against a separate literal target. It saves and reloads the full native workspace, freshly reconstructs the second product through Run → Digest → Run ancestry, and checks that the digest’s real 4-base strand offset survives. Additional groups reject equal-content wrong-event aliases, altered source snapshots, missing retained records and repeated mixed roots that exceed the shared ledger. No browser or application network checks are involved.

Candidate capability inheritance is also checked along the mixed path. If any descendant uses digest reconstruction, every enclosing CGP envelope must declare schema 21 or later. The traversal carries the minimum enclosing CGP version through digest wrappers; a newer inner candidate cannot launder the operation through an older outer envelope. A fourth fixture changes only an actual old-operation wrapper’s outer version header to 17/20, retaining its complete payload and checksum, and expects rejection while a wholly old-operation schema-17 tree remains readable.
