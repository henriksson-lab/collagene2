# Annotated protein flat files

`protein_formats` is an independent MIT implementation of explicit **GenPept** and **UniProt/Swiss-Prot text** import and normalized export. It does not reinterpret a DNA GenBank document as a protein. The source `aa`/`AA` length declarations select amino-acid coordinates, the native alphabet is `Protein`, and topology is linear. No duplex ends, native physical material, atom identifiers, or verified cloning history are inferred from accessions, feature notes, `/coded_by`, database cross-references, or review labels.

The primary format references are NCBI's [GenBank/GenPept release notes](https://www.ncbi.nlm.nih.gov/genbank/release/216/) and [flat-file structure documentation](https://www.ncbi.nlm.nih.gov/genbank/samplerecord/), plus the [UniProtKB user manual](https://web.expasy.org/docs/userman.html), especially FT, SQ, and amino-acid-code sections. The implementation does not borrow code from another cloning application.

The public API is:

- `detect(bytes) -> Option<Profile>`: a content hint; import still validates every record.
- `import_bytes(bytes, Profile::{GenPept, UniProt}) -> formats::ImportReport`.
- `export(molecules, profile) -> formats::ExportReport`: normalized current-model exchange, with explicit loss warnings.
- `export_with_options(molecules, profile, &ExportOptions)`: optional explicit `locus_date`, `uniprot_accession`, and `entry_name`. Identifier overrides require one record.
- `InsdcDate::new("26-NOV-2026")`: validates a real calendar date, including leap days. Core code does not read an OS clock.
- `original_bytes(molecule)`: exact immutable source-record attachment, including CRLF/BOM and inter-record whitespace assigned to that record. This is original evidence, not an export of an edited sequence.

Accessions, entry names, descriptions, sequence versions, organism text, and original location strings are retained. Repeated accession lines are collected. Unknown header/reference blocks remain in the exact original attachment; normalized output does not pretend to reproduce them. Source records are retained as bounded base64 chunks with a BLAKE3 digest, avoiding a single oversized native metadata value. Their digest detects inconsistent attachment data; it is not an authority signature. Source attachments remain original after edits. The adapters never put a protein record into the native `original_genbank` nucleotide citation mechanism.

GenPept features use the fixed feature/qualifier columns and their own protein sequence section. Numbered residue lines must agree with the current sequence offset; embedded digits are rejected. `join(...)` and `order(...)` preserve bounded location trees. Quoted multiline qualifiers and doubled embedded quotes are decoded without turning a `/coded_by` nucleotide reference into the protein's own coordinates. Protein complement/between-base/remote or unsupported locations remain unresolved with review flags. Exact range positions outside the actual protein are not clipped or swapped into apparently valid coordinates.

UniProt import distinguishes historical start/end FT columns and prose continuations from current single/range FT locations and quoted qualifier continuations. Old `/FTId` values are retained and normalized to `/id` on current export. Current qualifiers such as ligand/evidence/id values remain feature qualifiers; they are not interpreted as native molecular authority. Unknown keys and unparsed qualifier syntax remain reviewable, with exact originals retained. `?`, uncertain numeric endpoints, and isoform-qualified coordinates remain unresolved; canonical coordinates are never guessed from isoform positions.

Coordinates are converted from one-based inclusive source coordinates into zero-based half-open native positions. **DISULFID and CROSSLNK are two endpoint residues**, represented by a join of two singleton locations, rather than a continuous interval containing the intervening sequence. Their UniProt writer checks that exact endpoint geometry before restoring `a..b`. A generic interval cannot silently become a verified disulfide or crosslink. Other feature kinds retain their source type and documented interval/site meaning.

UniProt SQ lengths must agree with ID and actual sequence length. A present CRC64 is checked against the UniProt reflected ISO polynomial (`0xD800000000000000`), initial zero and final XOR zero. This differs from ECMA CRC64 and from all-ones initialization/final-XOR variants. Missing legacy SQ checksums produce an explicit warning. Source molecular weight is retained as source text, not adopted as a current computed property.

Normalized UniProt export calculates a fresh CRC64 and uses the existing native protein-property engine on an explicit sequence-only projection for the rounded unmodified, reduced, free linear-chain average mass. This is the SQ-defined primary-chain quantity, not the mass of an annotated modified material; the original molecule's native PTM/crosslink mass guard remains unchanged. It refuses unresolved residue identities or stopped sequences when an honest SQ mass/sequence cannot be supplied. It requires explicit valid UniProt accession metadata or an identifier supplied in `ExportOptions`; it never invents an accession or database review. Generated entries are marked `Unreviewed` and include a generated-exchange caution. This is a compatible exchange profile, not a complete UniProt database submission record.

Normalized GenPept export uses an explicit validated caller-supplied export date or the retained source LOCUS date. It never invents a historical placeholder date. That date is documentary export/header data, not a biological event time. Names/accessions must be safely representable tokens. Unsupported current-profile locations, unknown UniProt feature mappings, overlong unbreakable fields, and unparsed source qualifiers cause a clear native/original/FASTA alternative error instead of a silent flattening or data-loss success.

Resource limits are 4 MiB per input/output, 1 MiB per retained record, 128 records, 64 KiB per input line, 4,096 aggregate modeled features, 16,384 aggregate qualifiers, at most 16 location levels, and at most 1,024 children in one location list. Native aggregate model/text limits also apply before returning imported or exported documents. No provider, external program, alignment engine, or OS process is required by these adapters.

The focused fixtures include independent GenPept literal coordinates and quoted qualifier oracles; legacy/current UniProt FT layouts; isoform/fuzzy unknown positions; endpoint crosslinks; exact CRLF/chunked multi-record retention; edited current-model export; unsupported/bounded cases; and explicit synthetic export identifiers/dates. A reduced excerpt from the real [UniProt P69905 record](https://rest.uniprot.org/uniprotkb/P69905.txt) preserves its complete 142-residue sequence and literal `15E13666573BBBAE` checksum as an independent oracle, with selected real annotations. It is labeled an excerpt, not a full database record. Biological source data retain their upstream attribution; the adapter implementation and independently authored fixtures are MIT.

The generic core text/byte importer recognizes protein profiles before trimming, preserving exact source bytes. Explicit `TextFormat::GenPept` and `TextFormat::UniProt` exports retain the normalized export warnings. Oversized annotated protein input is still recognized and rejected by the protein bound rather than falling back to nucleotide GenBank parsing.

The existing File menu shows GenPept for protein documents and an additional UniProt option. A compact dialog accepts an explicit entry/accession when needed and a real UTC export date supplied by the UI. It prepares and displays the complete warnings before saving, captures workspace/document/head/revision pins, and awaits the existing native durable export acknowledgement or browser download result. It never silently substitutes DNA GenBank output. Exact original protein attachments have a separate clearly labeled export. No new global toolbar controls were added.

No compiler, browser, provider-network application probe, or external scientific tool was run by the adapter worker. Parent-coordinated compiler/fixture results must be reported separately; platform/GUI acceptance is not established by source integration.
