# Saved native templates in TOPO preparation

The TA/directional TOPO preparation panel can explicitly choose the retained run
origin of its insert PCR template. This connects a named native cloning product
to new exact-PCR synthesis, declared vector activation, actual transfer geometry,
ordered processing, final target verification and named reusable product output.
The original source documents and independently declared target remain unchanged.

## Material boundary

`topo_run_preparation` accepts an exact source role, selected native Capsule and
original TOPO declarations. Borrowed model/count guards precede source copying.
Documentary preflight and response checks establish request identity only; they
never supply chemical authority. Each actual inspection replays the capsule's
complete originating candidate against its own original target and requires the
selected event/revision and actual private material to agree. The tracked template
must have complete aligned strands without nicks. Staggered, nicked, reference-only
or unreconstructable templates are withheld rather than repaired or materialized.

Only the insert template role can use this route, and only as the template of an
explicit ExactPcr material recipe. It cannot also supply Prepared strand intervals.
Vector strands remain explicit original-source preparations; no activation,
phosphorylation, inherited strand atoms, implicit flap removal or host repair is
inferred. New PCR strands do not inherit the template's positional modifications.
All separate components, source-call mappings and processing limitations remain in
the native graph review.

Orientation, annotation/contour, independent-target and ordered-action inspection
share the existing scientific implementations. Public standalone APIs retain their
original source restrictions; no marker stripping or imported Duplex handoff is
used. UI requests include the selected origin in their stale/source checks and
attest it again against the current native workspace before candidate creation.

## Candidate and outputs

The selected ordered-processing candidate is compiled as:

1. `ReconstructRunProduct` from the exact saved input and retained origin.
2. `TopoActions`, with only the PCR-template role wired to that fresh step.

Ordinary Verify reconstructs both steps afresh against the unchanged independent
final target. The shared finalize/history/native archive and HTML/PDF paths retain
the complete source-event dependencies and origin recipe. Reuse remains conditional
on actual representable product material. Component choice is not experimental
isolation, kit efficacy or proof of laboratory success.

The older standalone nick-only/ProcessedTopo lane is not offered for a saved
PCR template because it cannot represent that upstream dependency. Use ordered
processing for explicit cleavage/sealing and the final material candidate. The
original checked-reference target view remains inspectable; it does not replace
the saved origin with a plain sequence input.

## Binary and validation contract

Worker89 appends request169 `InspectTopoRun` and result159 `TopoRunInspection`.
The response wrapper binds the whole task, literal source revisions, selected role
and complete capsule. Its inner scientific report retains its existing context;
there is no rewritten receipt or restored imported authority. Receivers with the
request call `Inspection::validate_for`, which recomputes both outer and inner
bindings without replaying scientific algorithms. Older worker88 frames reject the
new request/result. Candidate20, native plan18 and science23 remain unchanged,
since the candidate uses existing operations and scientific semantics.

Four literal fixture groups cover saved ten-base PCR material producing the
independently specified 24-base directional TOPO circle, explicit processing and
finalize/archive/reuse; changed source/origin/role, Prepared misuse, staggered
material and wrong target; worker-version and outer/inner binding checks; and
orientation/projection/target/action inspection. Tests and compiler checks are
run by the coordinated parent batch; no browser or application HTTP checks are
part of this source change.

## Explicit primer-order extraction

Plan oligo extraction now reads actual ExactPcr declarations embedded in Topo,
CheckedTopo, ProcessedTopo and TopoActions. Each forward/reverse use retains its
complete ordered DNA, annealing/tail boundary, original name, material ordinal,
outer plan step and exact Input/Step template binding. Saved-origin primers remain
historical provenance and are not reordered. No binding coordinates or amplification
success are guessed during this declaration-only extraction; actual PCR geometry
remains in fresh verification evidence. Separately declared post-PCR 3′ additions
are not appended to ordered primers.

Prepared vector strands and their activated termini are supplied material, not
inferred synthesis orders. Their original coordinate intervals and orientation
remain in the native plan. Derived Prepared sources or prepared intervals carrying
original oligo-order evidence make the order incomplete and prevent saving a
partial primer collection; no sliced/reversed or chemically activated vector is
flattened into an oligo. Missing/ambiguous roles and forward references reject.
Two additional fixture groups check all four TOPO operation wrappers, literal
primer tails, source mappings, new-versus-historical primer separation and these
unsupported preparation boundaries. The end-to-end fixture retains
`save_primers: true` so native output capture exercises the actual order artifact.

Saved-origin completeness is retained independently of the local PCR/TOPO graph.
The inspection wrapper exposes `origin_incomplete`, an excerpt of fresh origin
findings, their full count and an explicit truncation flag (at most128 findings,
2048 characters each). UI/MCP do not label a locally reconstructed product as
closing an incomplete origin's search. A seventh literal fixture assembles14+8
bases with declared4-base homology under the exact106-comparison reservation:
the18-base product is sealed and reusable, while terminal-alternative search is
incomplete. New TOPO PCR produces the24-base reference but final verification
remains Incomplete and output requires the existing explicit conditional-save
policy. The saved primer collection still contains only the new PCR oligos.
