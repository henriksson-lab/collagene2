# Prepared-substrate Golden Gate alternatives

`prepared_golden_gate` inspects finite alternatives over explicitly declared prepared rows, then allows an explicit unverified native-plan selection. It does not replace the independently supplied target, prune inconvenient candidates, or infer experimental uniqueness from an ordered ligation check.

A request contains the existing ordered ligation recipe and explicit `GoldenGateOptions`. Original source inputs and the target are revision-bound before copying or hashing. The ordinary ligation preview is reconstructed once through the existing verifier. Its private helper additionally returns the actual raw-orientation prepared duplexes from that **same** pass: step sources use the retained private trace, while original input references use only the existing native intact-reference assumption. Serialized molecular metadata, endpoint summaries and imported pool reports never restore private physical state.

Only when all requested prepared references and duplexes are available does the existing `golden_gate::simulate_reconstructed` engine redigest those substrates and enumerate its bounded alternatives. Missing preparation or physical state returns the full bound ordered preview, explicit missing row indices, `pool=None` and no invented candidate assessments. An available subset is never substituted for the complete requested role list.

**Scope is the selected prepared substrates after any requested digest isolation, repair and treatment.** Discarded digest fragments and uncut material from the original source/amplicon reaction are not automatically restored to the pool. Carryover reported by the underlying engine refers to these prepared substrates only. This is not a complete original one-pot reaction or all-carryover cycling model; that broader workflow remains separate work. Complete cleavage assumptions, tracked-modification limitations and the original verifier findings/assumptions remain retained.

The engine preserves finite candidate paths, subsets, one-fragment self-products, recuttable products, prepared-substrate carryover and all search bounds/truncation reasons. Recognition motifs recreated at junctions are rescanned by the existing engine. One-copy pool-fragment enumeration is not an exhaustive real-mixture search and cannot rule out repeated-copy concatemers, incomplete digestion or other laboratory products.

`both_orientations=false` refers to the raw stored prepared substrates. It does **not** mean the ordered recipe's per-row `reverse` choices filter the pool. Those flags still describe the separate ordered ligation preview. This distinction is explicit so a user can compare that ordered proposal with the declared pool scope without silently forcing it to win.

The report retains the request, exact independent target, full ordered preview, full finite pool, missing physical roles and one assessment per candidate. Assessments contain canonical directed/physical sequence keys, readonly target correspondence and source-role indices. Source roles are unique zero-based recipe row indices in first path-appearance order; the complete path separately retains every actual digest-fragment choice. Circular rotations are allowed for target correspondence under the existing policy; reverse complements remain distinct directed choices. Correspondence alone is neither a selection rule nor experimental confirmation.

`Selection` specifies the parent context, candidate index and both exact sequence keys. Pure `select` validates that receipt and refuses a recuttable/non-site-free candidate. It clones the original source-bound plan and replaces **only** its final ordered `Ligate` operation with the existing native `GoldenGate` operation over the raw prepared-source references, options and explicit candidate index. Every original input and preparation/treatment operation remains, including roles unused by a selected subset/self-product. No pool duplex is fed back as a materialized input. No scientific kernel is rerun by selection.

The resulting selection report is deliberately an unverified proposal. Fresh native plan verification reconstructs all original preparations and pool alternatives again, preserves truncation/cleavage assumptions and compares the selected actual product with the separately bound target. Choosing a self-product remains possible, and a wrong independent target remains invalid. A reported candidate from a truncated finite search does not make omitted products disappear.

Inspection contexts bind actual original source revisions, target and full request; selection contexts bind the parent context, explicit keys/index and derived plan. Readonly validation checks the compiled recipe/prefix, target identity, retained physical/report shapes, canonical keys, path/source-role mappings, target-comparison values, recut and completeness consistency. These are bounded consistency checks, not authentication of arbitrary imported evidence or restoration of physical authority. Hosts must compare current request/event contexts before presenting a worker response as current.

Existing source/preparation/model budgets remain, together with the underlying finite engine's 1–32 input and fragment-depth bounds, up to 1000 products/one million states, 128-fragment pool and 16 MiB retained duplex-base budget. Report and selection serialization remain bounded. The public old ligation preview API and serialized DTO are unchanged; it delegates to the private same-pass helper and discards the additional private states when they are not requested.

Five focused fixtures independently cover two shared-ATGA-fusion sources with self-A, self-B and full-target physical groups; explicit full selection plus native verification, and self selection against the wrong target; retained original preparation prefixes; missing preparation and metadata-only physical refusal; capped enumeration and explicit prepared-circle carryover; a recognition motif newly formed across a junction; raw orientation versus ordered reversal; and stale/forged context, key, role and target-assessment rejection.
