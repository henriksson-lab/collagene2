# Codon design in the web application

Open a protein document or a complete, concrete, linear DNA coding sequence, then choose **Codon design**. The active document defines the required protein. **Design coding DNA** searches synonymous coding sequences under the selected genetic code and explicit constraints. Translation uses internal-codon meanings and preserves a single terminal stop where present; initiation and expression are not inferred.

Choose one **Codon preferences** source: **Uniform**, **Custom integer weights**, or an available curated reference host. A host selects its declared genetic code and locks that control until you switch to Uniform or Custom. Its provenance section shows the reference assembly, admitted/excluded loci, internal-codon count, curation policy and pinned profile identity. Host preferences describe observed reference-CDS usage; they do not predict expression or provide a CAI claim. An unavailable catalogue leaves Uniform and Custom usable.

Editing the custom text selects Custom and replaces the active preference source. Enter 1–64 distinct concrete DNA codons with nonnegative integer weights, one per line, such as `AAG 100`. An unspecified codon has weight 1, and zero excludes a codon. An empty Custom draft is an error; choose Uniform for equal preferences. The retained custom draft has no effect while Uniform or a host is selected. Scores are sums of integer preferences. Forbidden IUPAC motifs are searched on both strands, including fixed-context junctions. Global GC applies to coding bases; local-window GC and homopolymer checks include the fixed left and right contexts. Context bases are not added to the returned coding sequence. Only complete local-GC windows are evaluated; constructs shorter than the window contain no complete window.

The search reports a candidate, exhaustive unsatisfiability, or an incomplete search. A feasible candidate does not establish global optimality if states were pruned. Work exhaustion does not establish impossibility. Search limits and pruning remain visible in the report.

A returned candidate passes through a **separate checking worker request** against the same source and options. The checker independently translates the actual DNA and evaluates every declared constraint. **Open designed DNA** and **Download designed GenBank** appear only for a complete passing check. Opening is an explicit action: computation leaves the source active and unchanged. The new document records the exact selected source event as its computational parent; the source head and undo/redo state remain unchanged. This edge describes the source-bound design/check operation, not nucleotide ancestry or a laboratory execution. The designed molecule retains the core's bounded source/options/engine provenance; ordinary native workspace storage and supported GenBank provenance comments preserve that evidence. Comments remain unverified producer evidence; the full native workspace/report and exact source are needed for rechecking. Historical metadata does not restore a current verification result or establish physical chemistry.

**Check an existing DNA candidate** accepts a plain DNA coding sequence and performs the same independent check. The supplied DNA receives portable source/options/engine evidence before checking, so its checked molecular revision is exactly the one opened/exported. Its origin remains explicitly user-supplied. Failed or incomplete checks display their violations and do not enable candidate opening/export. **Download codon report** exports the design and independent checker evidence as JSON; the browser uses an 8 MiB streaming output bound.

Changing the source document, exact source history event, workspace epoch, any option, or the supplied candidate invalidates results and terminates the pending worker. Unmounting the panel terminates its worker, and obsolete responses cannot re-enable export. These identity checks distinguish two documents whose molecular content happens to be identical.

Browser development coverage is in `scripts/codon_browser_qa.py`. It uses synthetic sequences and independently specified peptide/codon cases in the actual WASM application. The application invokes no external scientific executable.
