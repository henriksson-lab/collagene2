# Reference-only BP/LR tools

Three session-scoped MCP tools expose the bounded reciprocal reference engine. They accept exactly two ordered `{role, document: {id, revision}}` sources and a mandatory full adapter `Request`: explicit `ProfileSnapshot`, reaction (`BP` or `LR`), engine limits and annotation limits. Role identity remains distinct even for identical DNA. All three tools optionally accept `plan_sources: [Source; 2]`; when supplied, the adapter derives the exact typed-plan slot roles and returns the slots alongside its result. Supply those same slots, request and returned selection to `propose_plan` with `RecombineReference`. Clients do not compute internal role hashes. Omitting the field retains standalone caller role behavior. Rich sources and the independent target are checked while borrowed before copying them.

The read-only resource `collagene://recombination/profile/manufacturer-context-v1` supplies an explicitly chosen manufacturer-context snapshot. Its complete profile, citations and revision must be supplied in the request. It defines particular sourced full-site contexts; it does not define all possible minimal sites, biochemical activity, reaction conditions or MultiSite rules. A caller can instead supply another fully pinned, validated profile as a declared hypothesis.

- `inspect_recombination` returns a bounded candidate page (`offset`, `limit` 1–25, default 10) and a complete immutable JSON artifact. Every candidate and reciprocal component remains in that artifact. No documents are installed and no alternative is selected automatically.
- `check_recombination_target` reconstructs all reference alternatives and compares an independently supplied immutable `target` under an explicit `TargetPolicy`. The response retains possible sites, ambiguity, unsupported geometry, incomplete search and model-scoped no-match evidence. A target is a requirement, never source DNA.
- `select_recombination_component` requires the adapter `Selection` (`batch_revision`, `candidate_id`, `component_id`), independent target and target policy. It reconstructs and checks again; only the specifically selected fully specified matching component becomes an immutable session document. Artifact and document publish atomically after capacity checks. Reciprocal component identities and annotation projection evidence remain available. A foreign/stale batch, mismatched component or wrong target cannot install a document.

Artifacts are read through bounded `read_artifact` chunks. Reference products carry explicit reference-only/chemistry-unmapped metadata. Imported metadata and saved positive JSON do not grant authority. Native causal history is recorded through a typed `RecombineReference` plan and the existing fresh verify/record workflow. The target is not a causal source-event parent. Reference ancestry remains chemically incomplete; it cannot be converted into physical PCR, annealing or other substrate authority by importing or re-exporting a document.

Worker schema 22 appends requests 73–75 and results 66–68. These use the ordinary 32 MiB envelope and exact adapter source/profile/order/options/target/selection revisions. Earlier headers reject these variants before owned payload decoding. Candidate schema 7 and run/workspace plan schema 5 carry the typed operation; the verifier is science-9. Historical layouts remain readable as historical data.

The tools do not accept paths, shell commands, credentials, remote profile URLs or permissions, and perform no runtime network fetch or external scientific execution. Source annotations and names are untrusted data. Full evidence can contain source annotations and sequences; clients should treat artifacts as private sequence data. Tool errors and resource limits never become absence or successful-reaction claims.
