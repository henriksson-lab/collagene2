# MCP target-free material derivations

The single `material_derivation` tool exposes five typed tasks inside an immutable, explicitly pinned session `WorkspaceRef`. The full MCP surface contains 189 tools; origin inspection describes both Run and Derived origins. All request structs/task variants reject unknown fields. Tools expose no filesystem path, network endpoint, database authority or installation claim outside the current in-memory MCP session.

`PreviewPcr { source, origin, forward, reverse }` checks the exact retained current source-document event. `OriginalReference` passes the native intact-original source guard; `Saved` carries only a small `MaterialSelection` handle (Run or Derived event selection). The server resolves and freshly attests the closed origin inside that workspace; callers never pass capsule bytes. The native `preview_pcr` helper returns reference-only PCR documents and complete geometry under the supplied source model, without making a target or material document. The structured reply contains bounded indices, preview revisions, lengths and reusable flags. Install accepts only `MaterialPcrChoice { selected_index, expected_preview_revision }` plus the full primers; it recomputes geometry inside the server and checks the explicitly chosen index/revision. The optional complete immutable JSON artifact includes reference documents, full geometry and primers for inspection, but need not be read or copied back to install a product. Preview does not add session documents.

`PreviewDigest { source, origin, selection, options }` derives the native source-role identity from that exact source event and uses the generic physical `inspect_digest` adapter. Saved Run and Derived sources all freshly reconstruct actual private strands. The bounded summary reports product/scan determination and incomplete-origin excerpts; the full JSON artifact retains actual strand/modification summaries and every retained fragment. Catalog complete cleavage is an assumption, not a methylation-permission or experimental completion claim. Preview creates no selected stock or target assessment.

`PreviewMismatchPcr { source, origin, forward, reverse, options }` reconstructs the exact selected source and runs the native mismatch-PCR kernel with both full ordered primers and explicit mismatch, 3′ matching and search policy. The response reports bounded product geometry, search/enumeration completeness, inherited findings and the native reusable predicate; its JSON artifact retains the full policy and products. A single certain non-overlapping geometry can be retained conditionally when enumeration is incomplete. Competing products cannot be selected as an isolated stock. Unsupported staggered or nicked template geometries refuse explicitly; no repair is inserted automatically.

`PreviewRepair { source, origin, method }` uses an explicitly declared origin. Saved material requires its retained origin; OriginalReference remains the explicit intact-reference hypothesis with unknown modifications and terminal groups. It reconstructs strands, modifications and ends under that source model before applying the explicit native repair method. The response and full evidence expose synthesized/removed bases, resulting physical geometry and inherited findings. This performs neither a new digest nor ligation/sealing, and creates no saved product until Install.

`Install { request }` accepts the external compact request: source event, small origin handle, typed derivation, product name and save-primers choice. Exact and mismatch PCR have forward/reverse primers plus index/revision choice; mismatch PCR also retains its explicit policy. Direct end repair retains its explicit method. Catalog digestion retains its pinned selection/options/fragment index. The adapter independently resolves native origin and recomputes the chosen geometry, then passes a full native request to the unchanged core. It rejects omitted/missing indices, stale revisions and unexpected capsule/geometry fields rather than selecting a different product automatically. It runs the real target-free installation, checks the complete receipt against the resulting archive, and atomically publishes a **new immutable session workspace**, receipt artifact and native archive artifact. Optional newly performed PCR primer collections are included in that archive by the native installer. Allocation and aggregate artifact/session capacity checks precede publication through the existing atomic workspace-output helper.

The explicitly requested source must be a current head in the pinned workspace, even if another document is the active tab. Install selects the requested source only in its private working copy before processing. This changes presentation context, never a biological head. The input session workspace, source histories and unrelated private documents remain unchanged. Each resulting workspace can be exported explicitly through existing artifact APIs; nothing is written to a local catalog or host filesystem automatically.

Native archive artifacts are read through the existing bounded `read_artifact` interface with base64 encoding. Receipt/preview evidence uses UTF-8 JSON artifacts. Inline PCR and fragment summaries are capped at 100 entries with visible truncation; full evidence is bounded at 32 MiB. Full native archives and their receipts are capacity-reserved together. Returned bytes and documentary receipts carry no reusable in-process physical state: every later native reuse replays source history again.

There is no fabricated independent target for any transform. The initial reusable exact-PCR profile requires one complete geometry; choosing an item from multiple reference previews does not imply isolation. Missing current events, stale workspace pins, unrelated/equal-DNA origins, changed selected geometry, marked sources passed as plain originals and unsupported chemistry are rejected. Current scientific engine checks remain in the native derivation replay.

The in-process SDK fixture imports an ordinary original DNA source with an unrelated active tab, previews PCR without creating documents, uses only small origin handles and index/revision choices, rejects a stale preview or missing index, installs a native PCR and both primer orders, explicitly discovers its Derived origin, previews/installs an actual EcoRI fragment, replays the resulting native archive and discovers its new origin. It verifies the tool input schema has no capsule or amplicon-geometry payload and rejects mismatched event/origin families, stale workspaces and unknown geometry/claimed-chemistry fields, then re-exports the original workspace and compares its unchanged bytes. No GUI, browser, HTTP listener, network request, key store or live filesystem is used.

The extended SDK fixture also installs literal mismatch-PCR tails and substitutions, re-digests the saved product, and directly repairs a selected physical fragment. It rejects stale policy, invalid indices, forged geometry, mismatched events and plain-source claims for saved material while retaining the original workspace unchanged. These fixtures run through the actual in-process MCP SDK; passing evidence belongs to the corresponding verification checkpoint.
