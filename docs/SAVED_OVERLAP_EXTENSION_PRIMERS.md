# Source-bound standalone overlap-extension proposals

The single-contribution planner accepts an immutable original or exact saved
Run/Derived source. `Request` requires `template_strand` and required-nullable
`material_binding: BoundOrigin { event, origin }`. Original references use Top and
null. Saved intervals use the explicitly selected actual stored-strand frame;
physical contribution reversal remains a separate declaration.

Public preflight, context, compile and design functions take the optional owning
workspace last. Saved requests require exact event, source and native-origin
ownership in that workspace. Public design freshly replays the origin once and
borrows its actual strand for anchored primer ranking. Neither a physical summary
nor a returned documentary coordinate frame can become native material.

The existing nonverifying borrowed compile phase remains shared with whole-
construct planning. Its caller already owns fresh upstream material, so it can
use a null local binding with an explicit native frame. This internal phase does
not authorize the public originless Bottom route. Actual frame and request strand
must agree. No original-source or transformed-stock fallback is added.

The report retains bounded documentary source-frame correspondence and two exact
identities: the public source/request context and the private borrowed phase's
frame context. Readonly validation checks the declaration, literal edits, selected
oligos and canonical reconstruction-prefix plan without restoring authority.
`validate_sources` additionally attests the current workspace and exact source.
The final native verifier independently replays the declared origin and all PCR,
extension and outer-PCR operations against the separately intended sequence.

Worker108 and the existing MCP tool carry the same required workspace argument.
The existing proposal panel captures an immutable source/workspace request,
rechecks current source/epoch on reply, and uses fresh workspace attestation at
review/apply. It preserves native frame and preparation orientation. Actual primer
application remains an explicit normal UI action.

Independent Run and Derived fixtures start from actual40-Top/44-Bottom strands,
use a stored Bottom domain and literal edits for a42-base expected sequence,
retain the reconstruction prefix and first-branch Bottom versus outer Top frames,
and reject changed event, missing owner, originless Bottom and wrong-frame requests.
Inherited origin uncertainty remains visible. These proposals do not establish
experimental amplification, isolation or final assembly success.
