# Atomic construct release and portable archives

Selected historical batch declarations can create named outputs through a fresh
private reconstruction. A saved positive batch result supplies no authority:
every selected row is compiled against its original independent target and passed
through the existing native output finalizer. Exact source events are attested
before any new output is staged, preventing later rows from consuming an earlier
row's newly created events by guessing their identity.

## Review and publication

Choose rows and explicit per-row output names, prepared-fragment visibility,
primer retention and incomplete-result acceptance. The worker retains one private
workspace, advances in order and exposes actual staged product/target molecules
for sequence/map review. These inspection molecules do not manufacture a full
verification report. Any failing row poisons the session; no successful prefix
can be published. Cancellation discards the private session.

Only a finished session can return a complete workspace and immutable
`combinatorial-release-v1` manifest. The manifest binds the batch, declaration,
combination, input/target events, run, actual product, named construct and optional
primer sheet. Source heads are not rewound. Historical list/open operations check
structure and retained events, while fresh protocol production additionally
recompiles current declarations to reject substituted/self-targeting run records.

The web installs all outputs through one guarded current/previous IndexedDB
transaction. Draft, options, workspace fingerprint, epoch and operation owner must
still agree. Cancellation closes the retained worker used for both reconstruction
and persistence encoding; token-owned commit leases prevent an old completion
from unlocking a newer write. Actual transactions retain their lease until their
outcome resolves.

## Portable ZIP

Choose all released rows or an explicit subset and any combination of GenBank,
FASTA, primer CSV/TSV and HTML/PDF protocols. The archive preserves original
manifest order, stable safe file paths, source/run/output bindings, file hashes
and format losses. Review all files and loss notes through pages before explicit
download. Sequence/primer-only export is labelled historical exchange. Protocols
perform a fresh current-engine check against the independently declared intent;
HTML and PDF share one private checked context per construct.

The ZIP is capped at 120 MiB, each file 16 MiB, aggregate uncompressed content 256 MiB
and 1537 files. Metadata is bounded separately. A limit fails the complete export
instead of silently dropping files or notes. Archive validation checks the ZIP
directory, declared file sizes/paths and whole-archive hash. It is a corruption and
binding check, not a claim of experimental success.

## Transport and MCP

Worker 58 appends jobs 131–135 for begin/advance/inspect/finish/export and results
123–127. Only explicitly whitelisted workspace-bearing envelopes use 128 MiB;
progress and staged inspection retain 32 MiB. Old schema labels reject new selectors
before payload decoding. Private sessions cannot be restored from JSON receipts.

MCP provides `release_combinatorial_outputs`, `list_combinatorial_releases`,
`open_combinatorial_release` and `export_combinatorial_outputs` using immutable
workspace/artifact references. It accepts no host filesystem paths and invokes
no external scientific programs. Together with the previous tools the registry
contains 146 operations.

Finite reaction-pool batch composition now uses exact candidate consent and a
single fresh native verifier pass; see [contract](COMBINATORIAL_POOLS.md). Library
topology editing, remaining cloning
methods and final browser/visual/performance acceptance remain in scope. This
increment does not establish a verified experimental library.
