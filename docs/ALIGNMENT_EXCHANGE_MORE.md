# PIR/NBRF, GDE flat, and SELEX exchange

`alignment_exchange_more` independently implements bounded stored-alignment exchange. It does not compute alignments, infer biological confidence, call external tools, or treat row identifiers/annotations as molecular authority. The intended appended `AlignmentFormat` variants are `Pir`, `Gde`, and `Selex`. Integration with the shared dispatcher, native attachment source validation, worker floors, UI, and MCP is a separate parent-owned step.

The API matches the existing exchange layer: `import_alignment(bytes, format, alphabet, name)`, `export_alignment(document, format)`, and `export_alignment_with_options(document, format, &alignment_exchange::ExportOptions)`. A crate-visible `export_rows` supports computed alignments without fabricating an original imported source. All paths use shared `import_parsed`/`validate_export_content`; document exports also validate retained-source identities and stale per-column annotations. Identifiers are never silently renamed/truncated. Original bytes, alphabet choice, source hash, and stable source-derived row IDs use the existing alignment model.

## PIR/NBRF alignment profile

The primary references are the Protein Information Resource's [database definition, Appendix C](https://proteininformationresource.org/pirwww/otherinfo/co2.pdf) and the [IPD-IMGT/HLA database's official sequence-format documentation](https://hla.alleles.org/pages/other/sequence_formats/). These describe record headers/type codes, a required title line, and a terminal asterisk. The implementation is original MIT code, not borrowed from another cloning project.

The compact alignment profile supports `P1` (declared complete protein), `F1` (protein fragment), `DL` (linear DNA), and `RL` (linear RNA). The caller's explicit alphabet must agree even for sequences containing only A/C/G/T. Circular `DC`/`RC`, ambiguous type codes, and unsupported punctuation fail explicitly: an alignment-row model that extracts linear reference molecules cannot silently erase circular topology. Native `PIR_TYPE` row annotations preserve the declared type. Protein export without a completeness declaration uses `F1` and reports that conservative choice, rather than asserting completeness.

The second physical line is retained as the row description. Whitespace in sequence lines is ignored; `-` is the supported alignment gap. Digits, modification punctuation, and dot-as-gap guesses are rejected. The first `*` ends the record, is never a protein stop residue, and cannot have trailing non-whitespace data on that line. A native protein row containing `*` cannot be exported as PIR. NBRF text sections after termination are retained as ordered `PIR_TEXT` row annotations, including citation continuations; no source feature or atom description becomes a native biological feature. Export preserves these modeled text lines, with bounded single-line titles/text and wrapped sequence data. Unequal row widths fail as alignments instead of being implicitly realigned.

## GDE flat profile

The [GDE 2.2 author's manual, Appendix A](https://home.cc.umanitoba.ca/~psgendb/doc/local/pkg/gde/doc/GDE2.2_manual.pdf) distinguishes flat sequence records from the separate tagged `{...}` format. Flat `#` records are DNA/RNA and `%` records are proteins. The explicit caller alphabet remains required; nucleotide symbols must validate for that selected DNA/RNA alphabet. Text/mask (`"`/`@`) records and tagged GDE are outside this profile and fail explicitly, rather than being discarded or interpreted as biological rows.

Optional nonnegative `(offset)` values are leading alignment-column gaps, not external reference positions. Offsets and source payload widths are retained as `GDE_OFFSET`/`GDE_SOURCE_WIDTH` row metadata. Shorter source extents are padded to the common width with explicit trailing gaps, with a retained explanatory layout note. Negative offsets fail under this nonnegative column-origin profile. Spaces are formatting, and `~`/`-` are normalized gap glyphs; no other punctuation is silently removed.

GDE export preserves an explicit retained offset only when the current row still has the corresponding all-gap prefix; incompatible/stale offsets are errors. It emits complete common-width suffixes, including trailing gaps, so extracting/subsetting a document does not silently shrink its alignment columns. Original shorter source extents and descriptions have no independent flat-file fields and are disclosed as normalization/loss notes. Exact originals remain downloadable.

## SELEX alignment profile

The primary reference is Sean Eddy's [HMMER 2.2 user's guide, SELEX section](https://eddylab.org/software/hmmer/2.2g/Userguide.pdf). This adapter implements the format only; it does not run HMMER or infer a model from its metadata. Data names are unique single tokens shorter than 32 bytes. Sequence blocks have identical ordered rows and annotation coverage. Internal spaces, `-`, `_`, and `.` are gaps; blocks may have shorter trailing row extents, which are explicitly padded. Shared text columns must be unambiguous. Tabs in data and names overlapping the sequence column fail; use aligned label columns and explicit gap glyphs. Exterior all-blank columns need explicit gap glyphs to distinguish them from indentation/layout. Meaningful source case is retained as a per-row `SELEX_CASE` column annotation and restored on SELEX export, without declaring uppercase/lowercase to be verified match/insert states.

`#=ID/AC/DE/AU/GA/TC/NC` are retained global metadata. Unique header fields and finite paired cutoff syntax are checked, without applying thresholds to any scientific result. `#=SQ` lines cover all rows in exact order, retaining source weights, database fields, source-coordinate strings, and descriptions as documentary row metadata. Unknown fields use standard `-`/`0` placeholders on export; no default weight or source coordinate is invented. SQ coordinate strings never become native external-reference coordinates.

Reference/consensus `#=RF/#=CS` map to per-column `RF`/`SS_cons`. Individual `#=SS` and the surface-accessibility `#=SA` extension attach only to the preceding row and remain opaque column codes. Space gaps in annotations become `.`; original glyphs/layout remain in source bytes. Comments are retained; `%` comments and tabbed comment layout are normalized to safe `#` comments. Unsupported machine-comment classes are explicit errors. Export emits supported metadata and annotations, preserving full current rows and case masks. Other format-specific annotations and CLUSTAL consensus are disclosed as losses, never relabeled as biological confidence.

## Limits and evidence

The shared limits apply: 8 MiB source/output, 1,000 rows, 8,000,000 aligned cells, 65,536-byte physical lines, and 20,000 annotation entries. SELEX data lines additionally remain below 4,096 columns; labels are under 32 bytes. Dimensions are checked before padding/row allocations, and offsets, aggregate cells, annotation coverage, source text, and output size are bounded. No partial/truncated document is returned on failure. All profiles are ASCII text with explicit LF/CRLF handling. The shared native alignment document remains the loss-aware format.

Seven focused fixture groups cover literal PIR rows/type/title/text/terminator behavior, circular/stop rejection, explicit GDE offsets and mappings, the GDE manual's real tRNA example, SELEX spaces/case/row/global/column metadata, the HMMER manual's variable-width block example, and malformed/bounded cases. Cross-format exports disclose unsupported annotations; extracted rows remain ordinary reference molecules with no source features or physical authority. No compilers, browsers, live provider requests, or external aligners were run by the implementation worker. Parent-coordinated native and end-to-end results must be recorded separately.
