# Regenerated SCF trace export

`scf_export::export(&traces::Trace, &Options)` produces bounded SCF 3.00 from retained chromatogram evidence. It never generates signal from a sequence, basecalls, rescales samples, estimates missing peaks or converts quality scales. The original attachment export remains the separate existing `traces::original_trace_bytes` path.

The exporter reimports the exact original attachment and applies only the declared forward/reverse-complement view. Channels, calls, normalized sequence, peaks, quality vectors and source format must match that actual evidence. Changing a presentation name is supported; editing trace samples or calls has no supported provenance contract and is refused. A source checksum alone does not validate arbitrary mutable trace fields.

Supported signal is four canonical A/C/G/T channels containing unsigned values 0..65535. `SamplePrecision::Smallest` chooses 8 bits when every retained sample fits, otherwise 16 bits. Explicit8-bit export refuses truncation. Version 3 stores channel-major second differences with modulo-width arithmetic, followed by peak indexes, the four independent accuracy vectors and calls. These arrangements follow the primary [Staden sample specification](https://staden.sourceforge.net/manual/formats_unix_4.html) and [file layout](https://staden.sourceforge.net/manual/formats_unix_8.html). All integers are emitted in network byte order.

The current strict profile requires all four `QualityEvidence::ScfAccuracy` arrays. ABIF scalar basecaller scores are not equivalent to these arrays and are explicitly unsupported; missing qualities are never replaced by zeros. The stored estimates are preserved as bytes without asserting calibration or Phred semantics, following the [Staden sequence record specification](https://staden.sourceforge.net/manual/formats_unix_5.html). Code sets 0/2/4 and exact stored symbols are retained; '-' remains a no-call projected to N, not a deleted call. Equal peak positions remain equal. Explicit reverse-complement views swap/reverse A↔T and C↔G signal/accuracy vectors and transform peaks using the existing native trace implementation.

SCF's [header specification](https://staden.sourceforge.net/manual/formats_unix_3.html) declares obsolete clipping fields and reserved storage; its [comment specification](https://staden.sourceforge.net/manual/formats_unix_6.html) defines a zero-terminated list of field/value lines. This writer emits only the current NAME comment, zero reserved storage, no private section and no implicit clipping. It reports omitted original comments/private data, nonzero reserved fields, obsolete clipping declarations, outside-section bytes and additional native metadata. Loss entries expose categories/counts rather than private comment values.

`Options { precision, loss_policy }` defaults to `Smallest` plus `LossPolicy::Reject`. Any documentary omission requires explicit `AllowDocumentaryOmissions`; the returned `Exported.losses` is the review inventory. Signals, calls, peaks and accuracy vectors cannot be omitted under that policy. Human-facing integration must display/review losses before saving or publishing. This module alone does not add a UI export control. Exported bytes are not original bytes and do not establish biological correctness or physical DNA chemistry.

Existing native trace sample/base/original-file limits apply; the writer also bounds metadata and checks the complete output length before allocation. No external programs or borrowed application code are used. Focused native fixtures independently construct v2 source records and assert literal v3 delta bytes, 16-bit wraps, A/C/G/T quality layout, no-call/reverse-complement behavior, coincident peaks, repeated v3 determinism, documentary-loss refusal and fabricated/missing-data rejection.
