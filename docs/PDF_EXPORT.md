# Embedded protocol PDF export

`collagene_core::output::pdf::export_protocol_pdf(&plan, &target)` reconstructs the exact bound plan at export time and returns `PdfReport`: PDF bytes, page count, computed status, plan/target revisions, scientific engine version and rendering warnings. It accepts no externally asserted report or status. Invalid and incomplete plans are useful drafts, conspicuously marked on **every page**; already reconstructed intermediates remain visible. A successful sequence check remains “consistent under assumptions,” with laboratory review required.

The PDF includes starting materials and their immutable revisions, retained retrieval provenance, ordered cloning instructions, PCR ordered/annealing/tail sequences, reconstructed product revisions, strand/end chemistry and retained nick descriptions, findings, model assumptions, alternative-search completeness and missing laboratory conditions. An intended target map is drawn with vector geometry from the same typed `svg::MapScene` used for SVG export. Compound spans, biological terminal strand arrows, uncertain dashed geometry, review outlines and scene omission/collision warnings retain their stated semantics. A target map is a reference depiction, not evidence that construction succeeded.

Pages use a fixed A4 layout with metric-aware line wrapping, long oligo/hash/URL wrapping, repeated status headers and revision/page-number footers. The exporter is deterministic for identical plan and target inputs: it inserts no current time, random document identifier, external resource, active link, script or runtime font lookup. Content and font bytes are embedded. It does not invoke a browser, PDF printer, downloader or scientific executable at runtime and compiles for native Rust and WASM.

## Text and licenses

The standalone [pdf-writer](https://docs.rs/pdf-writer/0.15.0/pdf_writer/) library writes PDF objects/cross-reference tables; [ttf-parser](https://docs.rs/ttf-parser/0.25.1/ttf_parser/) supplies static font metrics. Neither library supplies cloning algorithms. The application code remains MIT. An unmodified Liberation Sans Regular font is bundled under its separate SIL Open Font License; see `crates/core/assets/fonts/LICENSE-Liberation.txt`. The locally installed distribution source was `/usr/share/fonts/truetype/liberation2/LiberationSans-Regular.ttf`; its upstream project and license are [Liberation Fonts](https://github.com/liberationfonts/liberation-fonts). The font is embedded whole, not renamed or modified.

Text uses a Type 0/CID TrueType font, an explicit CID-to-glyph map, actual advance widths and a ToUnicode character map so supported Latin, Greek, Cyrillic and scientific symbols remain selectable/searchable. The structure follows [ISO 32000-1:2008, particularly sections 9.7 and 9.10](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf). The exporter does not claim complete bidirectional or complex-script shaping. Unsupported/missing glyphs, combining scalars and formatting controls are visibly written as `[U+XXXX]` escapes with an explicit warning and a printed rendering-limits paragraph. Nothing is silently dropped; original Unicode remains in the source documents, and the plan title also remains in Unicode PDF metadata. This is not PDF/A, tagged PDF, or a claim of accessibility-standard conformance. Full script shaping and richer type design remain future work.

## Bounds and validation

Input documents validate before verification, with a streaming serialized plan-plus-target limit of 32 MiB and at most 1,000 inputs/steps. PDF generation rejects overflow rather than quietly dropping steps: at most 256 pages, 512 KiB of text/layout work, 4,096 distinct encoded glyphs and 16 MiB output. Existing source/model/map/verifier limits still apply. In particular the bounded map may abbreviate labels or omit geometry and prints the corresponding scene warnings. A document exceeding the PDF bounds returns an explicit error; HTML remains an independent export option.

`cargo test -p collagene-core --test formats reports::pdf:: --locked` exercises a separately written narrow PDF reader for cross-reference offsets, literal strings and ToUnicode extraction; all status headers, bound revisions, Unicode and hostile-looking text, missing glyph/shape reporting, vector maps, full multipage step retention, exact deterministic bytes, PCR tails/chemistry, retrieval provenance and limits. The tests invoke no external program. Optional development validation can set `COLLAGENE_PDF_FIXTURE=1` to write `/tmp/collagene2-embedded-protocol.pdf`, then inspect it with an independent PDF viewer/text extractor. Those tools are development checks only, never an application requirement. A local independent Poppler check (`pdfinfo`, `pdffonts`, `pdftotext`, `pdftoppm`) successfully parsed and rendered linear-compound and circular-origin fixtures: A4 PDF 1.7, embedded CID TrueType/Identity-H with Unicode extraction, all status/page headers retained, and no JavaScript/forms/encryption. These checks are not a claim that every PDF reader or accessibility standard has been validated.
