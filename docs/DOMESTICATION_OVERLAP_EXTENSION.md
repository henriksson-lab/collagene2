# Domestication by original-source overlap-extension PCR

`domestication_preparation::Route::OverlapExtension { options }` complements the current inverse-PCR route. It consumes a whole original DNA source in its existing orientation and accepts either linear or circular topology. Imported/saved physical-source markers are refused; this route does not flatten a saved product or use the recoded reference as PCR stock.

The native source/CDS checker validates every explicit selected substitution, catalog/site scope, retained site, protected base and affected reading frame. Its independently built intended target is frozen **before** native primer ranking. Only the original DNA and literal expected/replacement edits enter the overlap-extension planner. The target is never used to pick a successful primer pair or product.

The planner's genuine nonverifying `Compilation` phase is shared with its ordinary `design` API. It still performs bounded native primer design and source-bound ranked PCR geometry searches. It supplies the actual left and right primer pairs, selected reciprocal extension and outer primer pair. No fabricated VerificationReport is constructed. The composed domestication plan is then verified once against the independently checked target.

The canonical `Prepared.plan` has four operations for linear DNA: left PCR from original input, right PCR from the same original input, actual overlap extension and outer PCR. Circular DNA adds explicit phosphorylation of the outer PCR product and intended circular ligation. There is one canonical plan and one actual VerificationReport. `Prepared.method` retains method-specific primer locations/options or all three OE call/design/search receipts and all six actual primer uses; it contains no second plan or verification report.

`proposal_ready` and `proposal_findings` describe satisfaction of declared primer-route constraints only. For inverse PCR this means the explicit construction parameters fit. For OE all three selected native pairs must establish their declared geometry under the requested filters. Failed/capped ranked searches retain an explicitly nonready diagnostic proposal. A final matching sequence cannot certify a fallback. Conversely a selected proven pair is not invalidated merely because an earlier ranked alternative search was capped. Physical verification and terminal-search uncertainty are separate; the actual report's status is never rewritten to manufacture readiness. Neither flag asserts global optimality, experimental success or isolation.

Only substitution patches checked against the actual source are supplied as literal edits. External forward/reverse outer tails must be empty, because this workflow declares a whole-source substitution-only target. Boundary edits without two adequate unchanged endpoint domains, excessive bridges/oligo lengths, unsupported filters or search budgets require an explicit different method. The compiler does not silently rotate or truncate the source. New PCR DNA uses the existing unmodified ideal-PCR model; no source methylation, terminal repair, nick sealing or vendor mixture is inferred.

The existing native design/planning budget reserves final OE verification; circular composition additionally reserves bounded terminal-treatment/ligation work and material under the same 100M comparison / 64MiB material ledger. Source/reference and full report serialization retain their existing independent bounds (32MiB report). Genetic inspection/checking uses its own explicit domestication limits. This is not an assertion that every nested computation shares one absolute wall-clock or empirical cost.

Current worker101 uses the existing preparation job/result. The current preparation engine is `domestication-preparation-2`; there are no obsolete result readers or parallel route wrappers. Existing HTML/PDF, order tables, run recording and generic Run reuse consume the canonical plan directly. Shared endpoint oligos can deduplicate in an order table, while all six uses and ordered 5′ tails remain documented.

Seven focused native fixture groups cover literal linear/circular products, source/branch/outer ancestry, annotation conservation, all primer uses, synonymous coding-frame checks, protected/wanted-site refusal, exact source/context/method/target tampering, native protocol/history/archive replay, capped terminal uncertainty, repeated-source geometry fallback, explicit readiness and source/filter/boundary limits. Existing inverse-PCR fixtures are updated directly to the canonical plan/method representation. GUI acceptance remains separate from native validation.
