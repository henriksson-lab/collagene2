# collagene-genomic-index

MIT, dependency-free Rust BAI1/CSI1 parser and BGZF candidate-chunk lookup. No files, processes, networking, decompressors or DNA/model dependencies. See [the integration contract](../../docs/GENOMIC_INDEXES.md).

`Index::parse(bytes, Format::{Bai,Csi}, &Limits)` returns sealed private state only after complete bounded parsing; `query(reference_ordinal, start, end, &QueryLimits)` returns merged `Vec<Chunk>` with `start()/end()` virtual addresses. Coordinates are zero-based half-open. `VirtualOffset::{packed,raw,compressed,uncompressed}` preserve exact u64 addresses; no virtual-offset subtraction is treated as byte length. `reference_count()/references()` expose read-only dictionary ordinals, bins, BAI linear entries and separate optional metadata counters. `original_bytes()` retains exact source evidence, `auxiliary_bytes()` keeps CSI-specific opaque data. CSI input is **uncompressed CSI bytes**; gzip/BGZF transport decoding belongs in a bounded host adapter.

Optional `bind(&Association)` pins a caller-declared source hash, source byte length and ordered reference names; `BoundIndex::query` requires the same expected hash. This declaration does not prove actual source content or valid alignment placement. The host must hash actual bytes, match actual dictionary order and independently verify selected records. Empty candidate output never proves no alignments/variants. Auxiliary bytes, metadata counts, linear offsets and CSI loffsets are imported assertions. Queries conservatively omit linear/loffset pruning, avoiding reliance on those claims for exclusion.

Two input passes count references/bins/chunks/linear entries and reserve a conservative retained charge before retained vectors/source copies. Counts, depth/coordinate shifts, EOF, optional unmapped count, duplicate/reserved bins, metadata shape and chunk ordering are checked. Query budgets cover candidate chunks and bounded logical search/sort work; they are resource policies rather than CPU instruction accounting. Whole-region lookup iterates stored bins with per-level binary searches; it does not allocate one entry for every possible coordinate/bin. Output sorts and merges overlapping or touching chunks. Metadata bins never enter chunk lookup.

CSI supports depth0..10 (bin IDs fit u32) and min_shift+3*depth<=63, including checked u64 large-coordinate boundaries. BAI uses fixed min_shift14/depth5. Hard parse ceilings: 64MiB source, 16,384 references, 1,000,000 bins, 2,000,000 chunks and linear entries, 4MiB CSI auxiliary data, 256MiB charged retention. Defaults are smaller. Callers may tighten all caps. Malformed input/cap failures return no partial Index. Queries reject empty/out-of-range intervals rather than guessing special unmapped-read regions.

Independent literal tests are authored for boundary bin lookup, merging, CSI geometry/aux data, distinct metadata counts, exact originals, declared-source association, full truncation sweep, duplicate/reserved bins, resource limits and maximum arithmetic. These fixtures have not been executed at this source-only checkpoint; parent coordinates native/WASM builds. Workspace registration requires only adding `crates/genomic-index` as a member; there are no dependencies or lockfile dependencies.
