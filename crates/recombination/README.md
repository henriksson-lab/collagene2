# Defined two-site reference recombination

This independent MIT Rust prototype computes a **defined two-site reciprocal exchange**. It is not full Gateway parity and makes no enzyme efficiency, host, selection, expression or cellular repair predictions. It depends only on `collagene-model`, serde/JSON and blake3. No external runtime programs, application source reuse, core dependency, worker, MCP or web changes are involved.

`recombine` accepts exactly two ordered, uniquely named source roles, a full-site profile, BP/LR reaction and explicit limits. A full site is matched exactly in both directions, including circular-origin spans. IUPAC-compatible possible sites remain evidence and cannot generate products. Cognate att1/att2 pairings use their sourced seven-base overlap. A port graph reconnects literal source reference segments; every source position occurs exactly once across all retained components. Co-sourced overlap evidence does not describe physical-strand ancestry. Features, producer metadata and original GenBank evidence are not copied to outputs; their explicit source maps permit a future core adapter to project annotations appropriately.

The versioned manufacturer-context profile is **opt-in**, through `manufacturer_context_profile()`. No automatic/default universal profile is installed. An absent full-context match means that context is unsupported by the declared profile; it does not establish biochemical inactivity or absence of other Gateway-compatible sites. att1.1/att2.1, MultiSite, intramolecular reactions, sequential networks, mutation tolerance and inference of undisclosed arms are outside this version. All components of the supported reference graph are retained, including the three-component linear-substrate case (two linear end products plus an internal circle). No DNA is dropped to force two products. An explicit component limit is checked on the port graph before any source DNA copy; it withholds an entire candidate atomically and marks the report incomplete. Odd relative orientation parity is also outside this paired-orientation cassette model. Compatible mixed-family parents, such as B1/P2 paired with P1/B2, are intentionally supported as two compatible reference exchanges. Their literal reciprocal products are checked independently; they are not labeled standard entry/expression clones or biological winners.

## Primary profile sources

`data/manufacturer-context-v1.json` pins eight full context definitions, exact official sequence/map URLs and raw SHA256 snapshots. There are no INSDC accessions in these manufacturer TXT files; none are invented. Snapshot edition is `2026-11-24.1`. `python3 data/derive_profile.py PRIMARY_DIR` is an offline development-only extractor, where PRIMARY_DIR contains the cited original TXT/PDF snapshots; runtime uses the embedded JSON and does not spawn tools. The three raw official sequence texts in `tests/fixtures/` preserve independent literal input evidence.

- [Gateway Technology User Guide MAN0000282 Rev1.0](https://assets.thermofisher.com/TFS-Assets/LSG/manuals/gatewayman.pdf), printed pp5–7 (specificity, modified sites and BP/LR diagrams) and p13 (25-base attB primer strings). The BP/LR diagrams contain abbreviated N75/N100 arms; those placeholders are **not** full sequence sources. The manual's primary mechanism diagrams and [manufacturer crossover FAQ](https://www.thermofisher.com/store/v3/products/faqs/11801016) identify canonical overlap1 `GTACAAA`, overlap2 `GTACAAG` (rightward displayed attP2 `CTTGTAC`). The reference switch is before the canonical overlap, hence after the reference overlap on a reverse site. This is a reference sequence convention, not a physical-strand chemistry simulation.
- [pDONR221 reference](https://documents.thermofisher.com/TFS-Assets/vectors/pdonr221_seq.txt), 4761 bases; [official map](https://documents.thermofisher.com/TFS-Assets/vectors/pdonr221_pdonrzeo_map.pdf): attP1 570–801 forward extraction, attP2 2753–2984 reverse-complement extraction. Both annotated contexts are232 bases, canonical overlap starts at82 (zero-based).
- [pDEST14 reference](https://documents.thermofisher.com/TFS-Assets/vectors/pdest14_seq.txt), 6422 bases; [official map](https://documents.thermofisher.com/TFS-Assets/vectors/pdest14_map.pdf): attR1 67–191 forward, attR2 1788–1912 reverse-complement. Both125 bases, overlap at8.
- [pENTR/D-TOPO reference](https://documents.thermofisher.com/TFS-Assets/vectors/pentr_dtopo_seq.txt), 2580 bases; [official map](https://documents.thermofisher.com/TFS-Assets/vectors/pentr_dtopo_map.pdf): attL1 569–668 forward extraction, attL2 705–804 reverse-complement. Both100 bases, overlap at83. Map attL1 is annotated complementary, but matching orientation here is explicitly the literal canonical-overlap direction; annotation strand is not silently substituted for it.
- [Cheo et al. 2004](https://pmc.ncbi.nlm.nih.gov/articles/PMC528927/), DOI10.1101/gr.2512204, supports the central seven-base cognate overlap, relative-orientation dependence, and distinct att1.1/att2.1 variants. These variants are not mixed into att1/att2.

The FAQ's long full-site strings disagree in length/context with the official annotated maps; they are not repaired or used as full-profile defaults. pENTR1A has a different attL1 arm from pENTR/D-TOPO and is not silently merged into this edition.

Annotated context boundaries are not asserted minimal functional attachment-site boundaries. P232+B25 pieces yield a99-base L arm combination plus the unchanged source-context base upstream, which can match the registered100-base L context; the reciprocal contains a158-base R context that includes the registered125-base context. L100+R125 yields a source-derived200-base P-like hybrid and B25. It does **not** regenerate the registered232-base P variant. An unmatched output-site variant remains explicit evidence. The manufacturer's43-base attR deletion discussion is biological context, not the arithmetic difference232−200 and never a missing-DNA fill instruction. The manual LR example uses a different destination vector, so our pDEST14 fixture is not claimed to recreate that figure's entire vector.

## API and interpretation

- `preflight`/`batch_revision`: bounded source/profile/options validation before cloning or hashing. Exact ordered source roles, molecular revisions, full profile and limits bind requests.
- `recombine`: bounded full-site search, every candidate's source-derived component Molecules, source maps, orientation/topology, and co-sourced junction evidence. Distinct placement alternatives are retained, even when sequence-equivalent.
- `complete`: computation completed within the declared profile/work limits, never whole-Gateway coverage. `graph_plans`, `components_withheld`, `materializations` and `materialized_bases` expose bounded work. `max_product_bases` caps cumulative attempted materialization bases, including attempts later rejected by report limits, rather than only installed outputs. `unique_under_declared_profile()` additionally requires one candidate, no possible ambiguous sites and no unsupported geometry.
- `audit_product`/`audit_conservation`: separate base-by-base segment/overlap reconstruction and global once-only reference coverage checks.
- `check_target`: fresh reconstruction from sources, comparison against an independently supplied target without copying its DNA. Linear sequence and topology are exact; circles allow rotation; reverse complement equivalence requires explicit policy. This is sequence/model consistency, not experimental validation. `search_complete` means bounded-profile execution only. Original reconstruction `diagnostics` and explicit `possible_sites`, `unsupported_geometry`, `ambiguous_source_dna` and `ambiguous_target_dna` flags are retained. `no_match_proven_under_model` is true only if matches are empty, search completed, no possible sites or unsupported compatible combinations remain, and both sources and target are fully specified ACGT. Even then applicability is only `DeclaredFullSiteProfileOnly`, never universal Gateway absence. Any uncertainty sets applicability to `Unresolved`. A literal IUPAC representation match may still be reported, but has `fully_specified_dna=false` and cannot be mistaken for verified specified DNA.
- `Report::validate` and `validate_bindings_for` are structural/current-binding checks only. An imported positive report has no authority. `replay` freshly rebuilds and compares the complete report.

Bounds cap aggregate source bases, work comparisons, sites, combinations, candidates, components per candidate, cumulative attempted materialization bases, serialized inputs/profile and report bytes. Before model validation, JSON serialization or hashing, borrowed source and target inspection enforces aggregate4096 features,16384 location nodes,16384 qualifiers,4096 metadata entries,8MiB text, per-string limits and depth32. Its iterative depth-first location stack never contains more than32 frames and never pushes all children. Target annotations share the source aggregate budget. Field lengths are checked before trimming/scanning strings. Imported report validation rejects any output feature tree, metadata or original GenBank claim outright, matching the producer's annotation-free invariant; nested maps, junctions, aliases, scalar strings and aggregate item/text sizes are checked before JSON. Counting serialization then rejects oversized JSON without allocating an equally large JSON copy. Missing or truncated search evidence cannot establish uniqueness or absence.

cargo test -p collagene-recombination --locked
cargo check -p collagene-recombination --target wasm32-unknown-unknown --locked
