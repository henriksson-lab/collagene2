# Retained elementary TOPO graphs

A retained TOPO graph is an exact native elementary source/transfer recipe, not an ordinary DNA material origin. Its attachment-bound selection names the canonical record hash and actual graph state revision. Selection covers the **entire graph**, including unreacted chains, released activation identities, nicks and byproducts. A component/reference seed selects a view only; it cannot isolate stock or discard graph state.

The current worker supports `ListTopoGraphs`, `CaptureTopoGraph` and `InspectTopoGraph`. Capture returns a new workspace plus source-bound receipt, changes no biological document heads and grants no target acceptance. Inspect freshly executes the native source/transcript. Canonical `ProjectTopoProduct` and `CheckTopoTarget` return one annotated Product/TargetAssessment shape; there is no second annotated-only route. Independent target policy, including permission for nicks, remains explicit.

The MCP `topo_graph` tool has List, Inspect and Capture tasks. All take an immutable session `workspace` reference. List uses an explicit bounded offset/limit; its summaries are documentary discovery, not replayed material. Capture requires exact source events, required-nullable ordinary PCR-template selections and a projected preparation. `SavedGraph` fields accept a small native selection, never caller-supplied capsules or reports. The server resolves graph and ordinary Run/Derived roots jointly from the exact workspace before any copy, using one aggregate ancestry budget. It then performs native science; hydration itself does not replay. Capture atomically publishes a new immutable session workspace, native archive and receipt. It does not overwrite the old workspace or adopt a live application library.

Existing TOPO MCP tools accept required-nullable `origin_workspace` (`null` for original-only declarations). Friendly preparations distinguish Original, SavedVector and ResumeGraph. SavedVector adds only the declared new insert. ResumeGraph uses the insert already in the retained graph and adds no duplicate PCR or strands. The saved-template inspector accepts required-nullable `template:{role,selection}`; a graph-only continuation uses `null`, rather than inventing a template role.

The native capsule is opaque canonical record bytes plus exact source snapshots. One shared ancestry walker handles graph, Run and Derived roots, including graph recipes inside native plans and ordinary origins inside graph records. Byte/base/step/depth limits apply before cloning and no supplied ProductGraph is restored. Every retained graph record must match an actual native attachment, exact source events and current record/state identity. Historical scientific engines remain documentary findings; only actual native execution constructs a fresh graph. Processing-modified graphs are outside this first retained elementary-graph scope and are refused.

Selected-document sharing follows graph selections only from actual typed native Run/Derived dependencies. It retains their exact graph records and source/run ancestry. An unrelated plasmid never expands to every saved graph, source document or private workspace attachment. Metadata, a supplied report, or a copied graph selection does not establish publication ownership. Standalone graph entity publication/export UI is outside this scope; full native workspace archives retain unconsumed captures.

The literal integration fixtures declare activated vector strands `AGGGGCATCCCTT` / `AGGGATGCCCCTT` and insert strands `CGAATGA` / `CATTCGA`. A one-transfer capture retains all 40 source calls and one remaining activation; a graph-only continuation applies the other transfer against independent circular target `AGGGGCATCCCTTCGAATGA`. Acceptance permits the two actual unsealed nicks explicitly. This verifies the declared model, not activation manufacture, isolation or experimental success.

Focused targets: core `topo_graph_protocol`, MCP `topo_graph_tools`, library-sharing `topo_graph_closure`. These source fixtures were prepared without executing a compiler, SDK server or application during implementation; the integration owner runs the combined checks.
