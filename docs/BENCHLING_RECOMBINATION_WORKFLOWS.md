# Benchling recombination and preparation workflow review

Reviewed **2026-11-25** using official public Benchling documentation only. No authenticated application session, local browser checks, screenshots, builds or scientific implementation borrowing. This supplements the existing [workflow decisions](BENCHLING_WORKFLOW_DECISIONS.md) and [design-review continuity audit](BENCHLING_DESIGN_REVIEW_CONTINUITY.md); it does not reopen their completed implementation gaps.

## What the public documentation actually establishes

| Workflow | Documented interaction | Boundary of that evidence |
|---|---|---|
| Gateway | The combinatorial tool lists Gateway as a Homology use case when fragments already contain ATT regions. Setup proceeds through assembly settings, bins, fragments and constructs. | This is not documentation of dedicated BP/LR selection, numbered-site compatibility, MultiSite reciprocal products, att-family conflict resolution or recombinase chemistry. [Combinatorial assembly guide](https://help.benchling.com/hc/en-us/articles/39922419457165-How-to-use-the-combinatorial-cloning-and-concatenation-assembly-tools). |
| TOPO | Focused searches of the official help and its molecular-biology tool index did not establish a dedicated TOPO design procedure. | Unknown documentation coverage, not evidence that the application lacks TOPO. Instrument “Benchling Gateway” articles describe a different product and provide no recombination evidence. [Official tool index](https://help.benchling.com/hc/en-us/sections/39551695726605-Molecular-Biology-Tools). |
| Manual primers | Select a template region, choose forward/reverse, edit one primer or a pair, optionally add tails/sites, name and save. Existing primers are found, selected and attached separately. | Creation, attachment, pairing and visibility are separate operations. Wizard automation explicitly uses Primer3; copying its interaction does not require adopting that deferred dependency. [Use primers](https://help.benchling.com/hc/en-us/articles/39072057302541-Use-primers). |
| Ordinary PCR | Link the selected pair, open the Pairs tab, choose Create PCR Product, configure output options, then Copy/save the product. Wizard-created pairs are already linked. | This does not document inverse-PCR circularization, mismatch acceptance, repair or competing-product resolution. [Run PCR in silico](https://help.benchling.com/hc/en-us/articles/9684267245325-Run-PCR-in-silico). |
| Mutagenesis | The reviewed current help establishes manual reference-sequence editing; a protein-analysis worksheet mentions site-directed mutagenesis as a laboratory technique. | Neither establishes a dedicated mutagenesis preparation algorithm or an inverse-PCR workflow. Reference editing alone is not a physical construction route. [Sequence editing](https://help.benchling.com/hc/en-us/articles/39110680274189-DNA-and-RNA-sequence-overview), [protein worksheet](https://help.benchling.com/hc/en-us/articles/9684194939533-Protein-Analysis). |
| Saving/reusing outputs | The assembly object retains in-progress work and remains after finalization. Finalization locks its editor and saves constructs, with optional primers and amplified fragments. Outputs expose Assembly History. | The help does not establish an “edit this finalized assembly as a new draft” operation, automatic downstream chemistry inheritance or a complete-history sequence export. [Combinatorial assembly guide](https://help.benchling.com/hc/en-us/articles/39922419457165-How-to-use-the-combinatorial-cloning-and-concatenation-assembly-tools). |

The ordinary wizard additionally documents selecting backbone/insert regions, reviewing the assembled preview, resolving errors, naming and saving. Its Gibson FAQ explicitly describes a sense-strand reference convention rather than a kit-specific exonuclease model. This reinforces the distinction between a useful design interaction and comprehensive physical simulation. [Assembly wizard](https://help.benchling.com/hc/en-us/articles/39656605989901-Create-assemblies-with-the-assembly-wizard).

Assembly History belongs to the assembled sequence's own tab; Benchling explicitly distinguishes it from the generic History sidebar's Lineage tab. [History-location clarification](https://help.benchling.com/hc/en-us/articles/17806823063053-Why-can-I-no-longer-see-the-assembly-history-in-the-lineage-tab). The March2026 release notes also identify a fix involving PCR product creation with existing primers, supporting that interaction without revealing its algorithm. [Release Notes Volume3,2026](https://help.benchling.com/hc/en-us/articles/45487239514381-Release-Notes-Volume-3-2026).

## Implications for the current Collagene plan

These are our design conclusions, not undocumented Benchling guarantees:

1. **Keep Gateway and TOPO explicitly method-specific.** The remaining F15 work in [PROJECT_PLAN.md](PROJECT_PLAN.md) requires more than generic homology joining. Retain source-pinned site contexts, literal candidate/site choices, reciprocal-component review, independently declared target and explicit physical-state limitations. Benchling's public Gateway mention does not justify weakening those contracts or claiming equivalent BP/LR/MultiSite support.
2. **Reuse the existing primer/PCR path.** Selection-to-forward/reverse-primer actions, the shared pair editor, saved oligo reuse and selected-PCR output saving already exist. Do not add duplicate shortcuts or import Primer3 to imitate the wizard. Distinguish editing a template, choosing a primer pair and saving its freshly reconstructed product.
3. **Make downstream reuse explicit.** Continue the actual product→producing run→exact source navigation and editable fork already described in the continuity audit. For reaction chaining, require the actual native material or an explicitly synthesized PCR product; a saved reference with matching letters is insufficient to inherit modifications, activation, nicks or molecular ancestry. This is our scientific requirement, not a demonstrated Benchling behavior.
4. **Preserve two kinds of history and export.** Keep the producing design/run separate from ordinary sequence edits. Exchange FASTA/GenBank files are useful references; native workspaces retain richer evidence. Public help does not establish automatic verified cloning-step HTML/PDF generation, nor that sequence exports preserve complete assembly history. Our protocol exports remain an explicit product requirement.

No newly documented Benchling procedure resolves MultiSite family ambiguity, TOPO processing chemistry, unsupported inverse-PCR geometry or independent-target verification. Continue the existing scientific implementation queue rather than inventing parity claims or adding enterprise folders, ELN, inventory and scheduling.
