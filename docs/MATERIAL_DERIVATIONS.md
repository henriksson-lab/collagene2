# Target-free native material derivations

`material_derivation` records ordinary exact PCR and catalog digestion without inventing an independent target or cloning-run assessment. The same record/capsule/history/replay interfaces serve both operations. A real assembly can subsequently reconstruct those saved inputs and check its own separately declared target. These functions are native Rust/WASM code and invoke no external program.

`SourceOrigin` is either `OriginalReference` or `Saved(MaterialOrigin)`. The original branch is an explicit intact DNA reference hypothesis; restrictive imported physical/reference-only evidence cannot enter it. Initial source modifications and terminal groups remain unknown. Saved Run, old Digest and new Derived sources use the common native `MaterialOrigin::replay` interface. Actual private tracked strands are freshly reconstructed, never deserialized from summaries or inferred from matching DNA.

`Request` binds the exact source event, origin, explicit product name, operation and whether the newly performed PCR’s primers should also be saved as a presentation collection. `Derivation::ExactPcr` retains both complete primers, domain/tail decomposition, explicit selected geometry and expected preview revision. The initial reusable PCR profile requires exactly one complete geometry. Multiple geometries remain reference previews: selection alone does not prove isolation. Newly synthesized product strands follow the existing ideal exact-PCR model: concrete unmodified bases, blunt ends, 5′OH/3′OH and no nicks. No source methylation or source nick repair is copied into the newly synthesized product.

The model reuses current preview selection identities and annotation projection. Saved material’s actual strand coverage is checked with the existing `pcr_material_preflight`, including its conservative restrictions on nicks and extra staggered-template geometries. PCR tails must be concrete synthesized DNA in this reusable profile. Missing sequence, ambiguous annealing, unsupported template coverage or competing products withhold material rather than guessing.

`Derivation::CatalogDigest` pins the embedded catalog identity, inspection limits and exact actual fragment index. Cleavage runs on freshly reconstructed private strands and preserves their real offsets, terminal groups and positional modification state. Complete cleavage remains a stated assumption rather than a methylation-permission check or measured enzyme completion. An undetermined bounded digest withholds material. This route supports another digest after a standalone PCR and after older saved Run/Digest/Derived sources.

`inspect_digest` and `digest_inspection_revision` expose a source/origin/catalog/options-bound generic preview for that same physical route. The result retains actual source duplex geometry, source/fragment modification summaries, recognition/fragment records and incomplete-origin excerpts. Its selected-fragment helper uses the shared borrowed cut-boundary geometry algorithm; no report-derived summary restores private material. The source-role parameter is explicit and part of the inspection context.

`prepare_install` atomically creates a derived document, exact source-parent history event and content-addressed native record in a new workspace snapshot. The PCR ID uses `pcr-`; digestion uses `material-digest-`. Both events have the exact reserved operation string `Target-free native material derivation v1`. Product references retain a restrictive context marker and duplex summary, so detaching the record cannot promote the document to an ordinary intact template. `install` returns an encoded native archive plus an exact installation receipt. Neither path overwrites the source or fabricates a target document.

The attachment kind is `material-derivation-v1`, media type `application/vnd.collagene.material-derivation`. `Record` retains engine versions, original workspace fingerprint, exact request/product pins, current material-state revision and incomplete flag. Historical scientific versions remain documentary readable, but fresh reuse requires the current native scientific reconstruction and exact reproduced product/state/limitations. Source fingerprints are immutable historical context; they are not compared to a later workspace’s changing private state.

A record package begins with the eight-byte magic `MDRV\0\0\0\x01`, a little-endian u32 JSON-payload length, a 32-byte BLAKE3 payload checksum and canonical JSON. The complete package is bounded at 8 MiB. `Capsule` holds bounded opaque package bytes, a duplicate checked product pin and the exact source snapshot. It does **not** embed a typed `Record`. Thus `MaterialOrigin::Derived(Capsule)` does not create an infinitely sized Rust type, recursively expanded JSON schema or recursively decoded record tree. Human-readable capsule bytes use bounded base64; binary transport uses bounded byte strings. Full serialized capsule evidence is capped at 32 MiB under the shared mixed-origin ledger.

`load_record_shallow`, `Record::validate_shallow` and `attest_record_shallow` are structural hooks for the common iterative native ancestry walker. The walker must charge opaque bytes and source models before decoding each level and share ancestry/bytes/bases/step limits across Run, Digest and Derived layers. Native workspace attestation verifies exact retained record bytes, source snapshots, event parents and reserved operation labels. It never replays chemistry inside a documentary validator or calls `Workspace::validate` recursively from those hooks. Sharing helpers expose exact source bindings, required run IDs and required derived product pins; opaque payloads need no ad-hoc substring interpretation.

`FreshMaterial` is not serializable and has no public constructor. Its six-part consuming bridge moves the fresh reference, tracked strands, incomplete flag and bounded findings/total/truncation state into the verifier. Origin incompleteness remains sticky after successful new synthesis or cleavage. Findings are bounded to 128 entries of 2048 characters, with explicit total/truncation signals; new local processing assumptions are shown before inherited excerpts.

Optional PCR primer collections are installed in the same returned archive as the biological product. They contain only the two newly performed PCR oligos with full ordered bases. `Receipt.primer_attachment` is installation presentation evidence, checked against a freshly rebuilt deterministic oligo table. It is deliberately absent from `Record`: selected sharing may omit presentation collections without rewriting native record bytes or breaking material replay. Full primers remain in the scientific request. A digest cannot generate a new order from historical upstream primers.

Six literal fixture groups specify ordinary PCR → restart → both actual EcoRI fragments → independent-target assembly → finalized saved-product replay; tailed primers and old saved Run/Digest sources; forged geometry/events/opaque bytes; atomic primer collections and presentation omission; an actual reusable incomplete sealed-homology source; and competing PCR geometries/detached material restrictions. The scientific checks use independently written literal sequences and geometry expectations, not a target fabricated for target-free processing.
