# Source-bound declared reaction quantities

`core::protocol_quantities` connects the existing exact `collagene-protocol-units` arithmetic to immutable cloning-plan/event references. It performs documentary native plan membership and arithmetic validation, **not chemical verification, physical replay, measured concentration checks, stock lookup or laboratory execution**. No scientific operation or biological status changes.

A Request selects only an actual retained Candidate by canonical plan revision or a SavedRun by exact run ID and canonical plan revision. Target and ordered input EventBindings must resolve to native full molecule snapshots matching that plan. Historical source and target heads may advance; exact retained events still resolve. A Candidate does not intrinsically store original event bindings: its first explicit quantity request is the caller's declared association, validated against the complete retained snapshots. SavedRun does store authoritative original input/target bindings and refuses equal-content aliases. After any preview/capture, changing an event changes its exact context. No current-head or equal-DNA substitution repairs an existing receipt.

Reactions identify explicit graph operation indices under that immutable plan revision. A material component may reference only an actual input of its selected operation, using the native `verification::operation_sources` dependency definition. Other components are explicitly named numeric reagent declarations with `source:null`; they do not amend the canonical chemistry. The arithmetic-complete flag covers ONLY the reactions/components actually declared. Unlisted operations, omitted required reagents and laboratory conditions remain unspecified. An explicit fill-only mixture can be arithmetically complete without being a validated reaction recipe.

All quantities use the original typed units crate (`protocol_quantities::units` reexports its types). Rational values stay exact, dimension tags are validated, and no hidden floating-point/zero/default concentration is introduced. Source/missingness fields in current requests are explicitly nullable. Direct component volume can be None; missing final/component volumes retain documentary draft findings and never calculate a fictional fill. Explicit zero remains distinct from missing. ToFinal requires a distinct named fill component. Without it, remaining volume stays unallocated and is a visible finding. Overfill, impossible dilution, overflow and zero increment remain native arithmetic findings, not fabricated negative quantities.

MassDilution and MolarDilution use the corresponding typed DilutionRecipe; their final volume must match the reaction's declared total. The actual STOCK volume contributes to the mixture. Optional quantization requires an explicit increment and mode; its rounded stock volume, absolute deviation, achieved concentration and target_reached flag are retained. Explicit rounding can miss a requested concentration while the arithmetic is complete. Inspect those actual results; no instrument accuracy is inferred. No DNA mass-ratio/length model is used: asymmetric sticky ends and modifications are not silently treated as ordinary duplex base pairs.

Public native functions: preflight, preview_revision/preview, capture, load_record/load, list_revision/list, open_revision/open and export_revision/export. Preview validates its exact request, engine, context and recomputed arithmetic read-only. Capture adds one canonical protocol-quantities-v1 attachment and proves all documents, histories, candidates, acceptances, runs and unrelated attachments remain unchanged. The host must still apply its source/epoch guard and atomically persist current+previous archives before announcing success. Stored documents use ONE canonical JSON byte representation; whitespace/noncanonical alternatives and unsupported versions are rejected consistently by load/open/export.

Open and List have current-workspace envelopes separate from the historical Preview context. List validates the workspace once, builds its index through current native run readers and caches selected native records under an aggregate32MiB bound. Quantity records total at most32MiB per listing. Summaries include exact selectors/pins for cheap discovery but are not cryptographic proofs of full record content. UI must validate the opened Preview against its actual bound scope. A valid-format record whose candidate/event dependency was removed remains listed as `available:false` with explicit findings, so it does not hide unrelated valid reports. Open/capture/export refuse unavailable bindings. Malformed record formats, arithmetic or attachment identities fail closed. No cached missing-plan restoration or silent deletion exists.

Limits:128 reactions,128 components per reaction,4096 components aggregate,128 records,4MiB per request/document/standalone companion/list envelope; combined protocol files cap at 16MiB with a 32MiB-minus64KiB serialized export envelope; existing native plan/event/model and exact arithmetic bounds also apply. Full source snapshots are not duplicated into the quantity document. Unit fields remain strongly typed in Rust and use the units crate's canonical JSON (nL and rational numerator/denominator strings); current core JsonSchema marks those imported types as opaque JSON because that independent crate does not expose JsonSchema. Parsing and validation still use the native exact types.

CSV, standalone escaped HTML and embedded PDF companions retain exact plan/target/input identities, declared values, arithmetic findings, dilution results and scope notes. The PDF uses the existing bounded documentary renderer with a distinct ReactionQuantities label, not a fabricated verified chemistry result. Combined HTML/PDF additionally include the existing freshly verified cloning instructions and a declared-quantity appendix, with separate arithmetic and molecular results; see [composition](PROTOCOL_QUANTITIES_COMPOSITION.md). Ordinary plasmid publication omits this documentary sidecar with omission counts; explicit broader designer-evidence sharing is separate. No inventory, ELN, schedules, automation or provider runtime is added.

The focused native `protocol_quantities` test target has7 groups: exact balances/canonical archive restart and all exports; missing/zero/unallocated/overfilled drafts; mass and quantized molar dilution with achieved/deviation; Candidate versus SavedRun equal-content event semantics; historical heads versus new context; deleted-candidate discovery alongside a valid SavedRun report; and canonical bytes/actual-operation-source/forged arithmetic refusal. Native and WASM integration checks are tracked in PROJECT_PLAN.md. Browser and application HTTP checks remain deferred; these fixtures do not establish GUI acceptance.
