# Original Collagene migration audit

The source/schema audit targets original Collagene commit [`33f682a7156b875be730e18fa019ce310c9e54f6`](https://github.com/mahogny/collagene/tree/33f682a7156b875be730e18fa019ce310c9e54f6). The new Rust adapter is independently implemented from serialization facts and the public XDNA layout. No original Java application/scientific algorithm or third-party parser code is copied or executed. Synthetic fixtures are explicitly labeled; real producer interoperability remains unverified.

## Original native XML

The authoritative writer is [ExportOneXML.java](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/io/collagene/ExportOneXML.java); [CollageneXML.java](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/io/collagene/CollageneXML.java) defines its project container. The MIME registration calls project files `.collagene`; the general importer also advertises `.seqfile`, without supplying a separate schema for that suffix.

| Serialized object | XML shape | Migrated semantics |
| --- | --- | --- |
| Project | `madgene` containing ordered `oneseq` elements | Multiple independently editable records, original record index and duplicate names preserved |
| Single document | `f` containing the same record children | Exact writer shape accepted; nested `sequence` wrapper also recognized as the old detector's alternate shape |
| Sequence pair | `sequence` attributes `name`, `su`, `sl`, `circular`, `notes` | DNA reference, topology, source-aligned upper/lower rows and notes |
| Annotation | `annotation` attributes `name`, `from`, `to`, `colr`, `colg`, `colb`, `orientation` | Label, zero-based half-open reference range, origin wrapping, orientation and RGB evidence; type is `misc_feature` because no feature type was serialized |
| Primer | `primer` attributes `name`, `sequence`, `target`, `orientation` | Full ordered DNA, original target/orientation and review-required binding footprint; no inferred tail/domain or amplification proof |

All annotations migrate as review-required. Source colors remain exact `color` qualifiers; current views may use their feature-type palette. Unknown record children/attributes remain in the complete original attachment and generate warnings. Unknown project-level record types, namespaces, duplicate/missing sequence children, malformed strand/range/color fields and unsupported encodings fail explicitly rather than partially importing a project. DTD/entity expansion is disabled.

The original model's coordinate convention is zero-based half-open. Its lower strand is stored left-to-right alongside the upper row, i.e. in complementary 3′→5′ display orientation, not as a second 5′→3′ sequence. Spaces represent absent cells. This orientation is independently confirmed by the lower-row getter, the [linear renderer](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/gui/paneLinear/tracks/QGraphicsLinSequenceItem.java) using the same column index for both rows, and reverse-primer extraction reversing the lower substring. The adapter projects source column intervals through non-space upper cells, keeping origin/reverse order; lower-only and zero-length/unsupported ranges remain unresolved. Both original rows remain available. Gapped or noncomplementary pairs carry the restrictive `ms-DNA` declaration, so the intact-duplex scientific model cannot silently replace them with a perfect complement. Imported source data never supplies trusted terminal phosphorylation, nick state or a reconstructed duplex.

The original primer [getRange definition](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/primer/Primer.java) places a forward oligo of length L at `[target-L,target)` and a reverse oligo at `[target,target+L)`. These are source footprints, not independent binding evidence. Circular footprints can wrap. Unoriented primers remain unresolved and all full oligos stay literal source evidence.

The serializer contains **no operation graph, project UUIDs, revision history, restriction-site caches, trace arrays, primer tails, terminal chemistry or nick fields**. Those cannot be recovered from files in this schema. Original annotation descriptions/notes beyond the serialized name were also not written; only the sequence-level `notes` attribute was saved. The new application does not fabricate missing history or materials.

## Original implementation defects are not migration rules

[ImportOneXML.java](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/io/collagene/ImportOneXML.java) detects root `sequence`, while its corresponding single-document writer emits root `f`. Its loader expects a child `sequence`, so accepting a bare root sequence as a populated record would be unsafe. The new adapter accepts actual writer containers and rejects the bare shape. The old loader does not restore the saved notes; the new adapter does.

The old nucleotide complement helper exchanges S/W ambiguity codes, which is inconsistent with their self-complementary allele sets. The new parser preserves the literal paired rows and quarantines contradictory evidence instead of reproducing that scientific bug. Range normalization also contains ambiguities for equal endpoints/full turns; zero-length/equal-endpoint source ranges are retained unresolved rather than assigned an invented full circle.

## DNA Strider / Serial Cloner profile

The implementation uses the format researcher's [plain-English XDNA specification](https://incenp.org/dvlpt/docs/binary-sequence-formats/index.html#xdna-format), checking the original Collagene importer only to audit migration differences. A narrow check of the standalone [Biopython XDNA adapter](https://github.com/biopython/biopython/blob/master/Bio/SeqIO/XdnaIO.py) confirmed the coordinate boundary convention; its code is not used.

Supported XDNA version 0 has a 112-byte header, big-endian length fields, explicit DNA/degenerate-DNA/RNA/protein alphabet and linear/circular flags. The header terminator must be `0xFF`. Source origin offset and comments remain evidence. An optional extension retains signed overhang descriptors plus up to 255 annotations, their descriptions, flags and RGB text. Feature coordinates are one-based inclusive; reverse endpoints are reversed before conversion. Wrapped intervals require circular topology. No extra sequence block is inserted between overhangs and the feature count; the original Java reader's extra read is not treated as a valid layout rule.

Overhangs are **unmapped physical evidence** and block intact-duplex assumptions. Nonzero display-origin offsets do not rotate bases; their feature-coordinate anchor remains unresolved pending producer fixtures. Protein reverse-strand flags likewise remain unresolved. Descriptions containing GenBank-like text remain literal notes rather than unvalidated phase/qualifier claims. Unsupported text encoding, flags, truncation, out-of-range lengths and trailing extensions fail explicitly. `.xdgn`/`.xprt` suffixes are recognized by other vendors, but are only supported here when their bytes satisfy this same profile; no suffix alone proves interoperability.

## Evidence, limits and remaining gates

`legacy_formats::{import_collagene_xml,import_xdna}` return ordinary import reports. `original_legacy_bytes` retrieves the exact input after verifying its BLAKE3. Entire XML projects remain attached to each migrated record, with native workspace blob deduplication across identical attachments. Input and materialized/native output are bounded to 32 MiB, with 1,000 XML records, 100,000 annotations/primers per record, 300,000 XML nodes, 64 nesting levels and the standard ten-million-base document limit. Retaining a large project in multiple standalone documents can reach the output cap before the input cap; this fails atomically.

The audited repository contains no biological `.collagene`, `.seqfile`, `.xdna`, `.xdgn` or `.xprt` migration corpus. Its checked-in XML files are launch/MIME configuration. `fixtures/legacy/serializer-shaped-project.collagene` is independently written from the serializer schema; unit tests hand-encode XDNA fields and use explicit reference slices/complements. Required next gates are real original single/project saves, non-ASCII producer encoding, nonzero-origin annotated XDNA, all supported program/extension versions, gapped/mismatched historical products and native/WASM/browser interoperability. Saving edited files back into legacy formats is not implemented. Standard text exports cannot preserve the complete source attachment or unknown physical semantics; retain native workspace/original files.

Uninterpreted sequence/material fields or direct child elements are retained but mark physical chemistry as unmapped, preventing a future nick/end-state field from being discarded while asserting an intact duplex. The web editor labels its calculated complement separately from original aligned source rows. Clipboard copying of a feature uses its exact biological orientation; unresolved/unknown-order source features do not yield an invented sequence.
