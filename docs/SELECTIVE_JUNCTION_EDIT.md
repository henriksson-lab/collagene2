# Selective junction primer proposals

`selective_junction_edit` builds on the existing independent junction-edit intent and regenerates only explicitly selected PCR rows. It does not replace saved/manual choices to make a target check pass.

A request contains the original source-coordinate assembly `base`, explicit junction `edits`, ordered `rows`, one explicit overlap length per junction, primer options and the existing advisory overlap profile. Each row is either:

- `Retain(FragmentSpec)`: preserve the entire preparation literally, including primer names/domains/tails, catalog selection, chosen digest fragment, repair and orientation.
- `DesignPcr {role, input_id, reverse}`: design one anchored pair against this row's adjusted original-source interval.

Row order, role, original input and orientation must match the base declarations. Output `designs` is aligned to **all** rows, with `None` for retained rows; `retained_rows` contains their ordered zero-based indices. Retained fragments are copied and checked by their serialized identity. They do not acquire the selected designer's minimum domain length, PCR-source eligibility or newly suggested tails. Their existing preparation rules still apply: retaining an impossible source/preparation does not waive the native compiler's restrictions.

The intended target comes exclusively from `assembly_junction_edit::build_intent`: adjusted original source cores plus declared literal junction inserts. This occurs independently of PCR or assembly simulation. Source coordinates and synthetic contribution ranges use that module's established convention; original sources are never rewritten or replaced with materialized fragments.

For selected row `i`, the oriented right-side addition is its declared synthetic suffix followed by the next adjusted oriented source core's prefix of length `overlaps[i]`. Its reverse complement becomes the original reverse primer's 5′ tail for a forward row, or the original forward primer's 5′ tail for a reversed row. The other tail is empty; the last linear row has no outgoing tail. Each selected pair is analyzed and ranked by the existing in-house designer with these complete actual tails already present. Tm keeps the existing annealing-domain definition, while the complete oligos participate in structure/pair screens. Calculation options remain explicit.

Homologies may vary by junction. The existing recipe supports positive lengths up to 10,000 bases; a selected PCR row additionally needs that complete addition and its domain to fit the 200-base ordered-oligo profile, and its downstream original core must contain the requested prefix. Retained rows may already carry different or incompatible preparations. The proposal keeps them unchanged and warns that the full recipe must be freshly reconstructed against the independent intent. It supplies no positive assembly, amplification-uniqueness, reagent or experimental verdict.

Borrowed preflight first bounds source models, base declarations, trims, annotations and literal inserts. Retained preparation text/catalog selections are guarded before their small specification copies, then passed through the shared native preparation guard. A target-free internal helper reuses the same source/preparation rules without inventing a dummy target; existing public preparation preflight still validates and charges its actual target exactly as before. Only selected rows incur new PCR-source, concrete-core, anchored-domain and full-tail design checks. Native preparation and selected design/PCR scan budgets apply, and the completed real recipe is passed through ordinary source preflight against the actual intended target.

All-retained proposals remain useful: they preserve declarations and allow a fresh full-recipe check without requiring unused primer-design length settings to suit those manual choices. Configuration text stays bounded and numeric values must be finite so revision hashing is unambiguous. New designs require empty option-tail slots; no caller-provided option sequence is silently discarded.

`design_revision` binds the engine domain, actual original source revisions and full request, including retained serialized preparations. Readonly report validation checks independent intent identity, exact retained bytes/index mapping, selected source intervals, actual ranked oligos/options/metrics and variable-homology tail geometry. Decoding evidence does not rerun design or establish authority. User edits must invalidate prior proposals and downstream reconstruction/order evidence.

Five independently specified fixtures cover a mixed three-row workflow: selected first PCR with a literal insert, retained named manual middle PCR and retained pinned EcoRV digest, with overlaps 15 and 18. They check an independent 68-base target and fresh complete reconstruction; incompatible retained rows remaining unchanged; reverse/circular variable overlaps; manual four-base domains outside the selected eight-base design profile; all-retained proposals; source immutability and byte preservation; and role/order/stale-source/work/receipt failures. The older all-PCR workflow and its fixtures remain unchanged. No scientific operation, verification engine, candidate or plan version changes.
