# Whole multi-parent reference exchange

This increment models a declared finite reference graph, with no physical-strand,
host repair, selection, yield or commercial kit success assertion. It extends the
separate two-parent reference workflow without changing its historical semantics.

## Inputs and classification

Supply two to five original DNA parents with distinct roles, BP or LR, explicit
specificity numbers1–16, and a complete caller-reviewed full-context profile with
source citations/hashes. Specificities select cognate families; a target never
chooses a site, pairing or candidate. All registered families participate in the
scan before reaction filtering.

At a common physical seven-base core, a certain full context strictly contained
in another certain context is suppressed for selection. Equal or incomparable
maximal contexts with conflicting families remain unsupported. Equivalent
same-family aliases enumerate once under a stable variant identity. Every raw hit
remains in the report. Ambiguous possible sites make coverage incomplete; an
incomplete all-family scan yields no candidates because an unseen longer context
could change classification. This policy is a declared recognition model, not a
biochemical claim about every possible surrounding sequence.

The primary-source review found that a genuine96-base L3 context is exactly a
prefix of a232-base P3 donor context. Filtering to LR before classifying all
registered contexts would misclassify a P3 donor. Adding an arbitrary extra base
to L3 would encode insert sequence as a universal site arm. Neither is permitted.
Acquired full biological source fixtures remain unbundled pending redistribution
terms; shipped tests use explicit independently concatenated synthetic oracles.

## Graph and evidence

All selected pairings rewire one source-interval graph. Every original reference
base is partitioned exactly once across all reciprocal and unreacted components.
Seven-base overlap co-sourcing is reference annotation provenance, not extra
output sequence. Reverse and origin-spanning sites retain explicit correspondence.
Candidate/component choice happens only after reconstruction. Work bounds cover
scan comparisons, partial and full pair assignments, whole-candidate copying,
components, serialized reports and cumulative annotation projection. A cap cannot
silently emit a partially accounted candidate.

The core adapter keeps conservative coordinate projections and unmapped feature
evidence. Reference-only and chemistry-unmapped metadata are mandatory; an
imported recipe cannot supply native tracked material. Typed operation21 retains
its complete batch in the generic reference-step evidence slot. A matching
independent target leaves verification incomplete because reference agreement
cannot establish physical chemistry. A downstream physical transformation cannot
promote these letters into a duplex.

The desktop panel accepts ordered original parents, a reviewed full-context
profile and an independent active target. Its built-in profile covers registered
manufacturer site1/2 contexts only. Other contexts require an explicit imported
profile; there is no universal MultiSite-kit preset. Results show candidate
networks, reciprocal components and limitations, support a fresh target check and
hand the selected component to the ordinary Plan verifier. Source/target events,
profile changes and workspace epochs invalidate displayed evidence. Profile
imports have their own generation guard and require fresh scope acceptance.

MCP exposes `inspect_multisite_recombination`,
`select_multisite_recombination_component` and
`check_multisite_recombination_target`. Optional native source pins attest exact
workspace/event ownership; a mismatch does not install a target-derived product.
The full batch remains an artifact rather than a truncated natural-language claim.
