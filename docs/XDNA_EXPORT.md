# Regenerated DNA Strider / Serial Cloner XDNA v0 exchange

`xdna_export` implements the bounded `collagene-xdna-reference-v0-1` profile. It is independently written against the explicit binary contract already supported by Collagene’s own `legacy_formats::import_xdna`, rather than copied from another application or parser. Literal byte fixtures specify the generated layout before testing reader roundtrips. Acceptance by vendor applications and compatibility with a producer-file corpus remain unverified; this is not a claim of complete native Strider/Serial Cloner support.

`review(&Molecule)` returns a source-bound `Assessment`. `export_xdna(&Molecule, Policy)` returns a `Report` with bytes, MIME type, `.xdna` extension, complete unmodified `suggested_name`, warnings and typed losses. Both use the exact current molecule revision. `Strict` refuses every reported loss; `AllowOmissions` permits only listed documentary omissions and never bypasses physical-state restrictions. The host must show the loss review and await its real native export acknowledgement.

The selected v0 profile has no reader-mapped embedded molecule-name field. Consequently the native name appears in `suggested_name` and an explicit `Name` loss; it is neither hidden in a comment nor silently truncated. Even a plain sequence therefore requires accepting this omission in the current API. A filename can provide display context on import, but the writer does not pretend this is an embedded-file guarantee. Exact native identity, folders, history and claims belong in a native archive.

The 112-byte regenerated header uses version 0, explicit current topology, type 1 for DNA or type 4 for linear protein, big-endian sequence length at offset 28, origin 0 at offset 32, comment byte length at offset 96 and marker 255 at offset 111. All remaining header bytes are zero. DNA/protein residues follow, then a literal ASCII `description` comment. RNA/type 3, ambiguous type-2 semantics and circular protein output are outside this writer profile.

The regenerated extension consists of marker 0, two Pascal strings `0` for the right and left overhang descriptors, and an unsigned-byte feature count. These fields do not carry native terminal chemistry, measured modifications or material provenance. Up to 255 features are supported; exceeding the bound fails rather than truncating. Each feature has ASCII Pascal strings for label, note, literal type, inclusive coordinates and RGB extra, plus current-location strand, visibility 1, reserved 0 and arrow 1. String fields are at most 255 bytes. Oversized, non-ASCII or duplicate textual fields are reported and omitted, never shortened or merged.

Feature projection accepts an exact contiguous range or one exact circular origin-wrap, including a whole complement of that wrap in its biological extraction order. Fuzzy, ordered, unresolved, mixed-strand, reverse-protein and discontinuous joins are omitted with a whole-feature loss. A forward half-open native range `[a,b)` becomes inclusive `(a+1,b)`; reverse strand stores `(b,a+1)`. Literal type keys are retained without substituting an invented type. The importer marks all annotations for review, so exporting a reviewed native annotation reports loss of that review state.

One native `color=#RRGGBB` qualifier maps to decimal RGB. A lowercase spelling roundtrips; other hexadecimal spelling reports the lexical normalization explicitly. Duplicate or invalid colors are omitted with a loss. Arbitrary qualifiers, original coordinates/display flags/opaque extras, metadata outside ASCII description and original INSDC/source files are explicit losses. Color and display defaults are never selected from stale original bytes. No original extension or padding is re-emitted after edits.

The shared `format_fidelity::reference_export_guard` rejects physical, damaged, single/mixed-strand, declared-terminus, modified or reference-only products, including recognized native producer markers. Retained nonzero or unresolved XDNA overhang descriptors are also refused independently of summary markers. Known modified/crosslinked protein annotations are hard refusals: accepting omissions cannot turn them into an unmodified protein chain. Use a native archive for those sources.

The implementation caps output at 32 MiB, features at 255, losses at 1024 and applies existing rich-model/source limits before processing. Seven fixture groups cover literal header/extension bytes, directional/wrapped coordinate bytes and extraction, linear protein, explicit losses, restrictive physical evidence, edited current output versus retained originals, and byte/count bounds. No external executable, network, browser or application smoke check is involved.

The module is registered in `core/src/lib.rs`. It does not add UI/MCP menus; those adapters must use the typed review and existing acknowledged download path. Exact imported source bytes remain available through the existing original-legacy download separately from regenerated current output.
