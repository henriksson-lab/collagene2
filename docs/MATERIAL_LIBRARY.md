# Actual-strand source library contributions

The current source library stores the same typed `assembly_intent::Selector` as an
ordinary assembly. A reference interval and a native stored-strand interval are
separate domains. `Design.material_bindings` explicitly binds exact source events
to retained native Run/Derived origins, with at most256 distinct native sources
and the existing aggregate native-source budget. Many choices may reuse one
binding; duplicate/conflicting or unused bindings refuse. A choice never acquires
its target source from physical-preparation metadata.

Native resolution attests complete original snapshots and all selected origins
before source copying, then reuses the shared intent resolver to obtain actual
stored5′→3′ calls, state pins, original-oriented edits and top annotation mappings.
The independent target is frozen before physical preparation. Bottom-only calls
receive no invented top-reference coordinate or annotation. Equal DNA from another
event, stale state, an absent native record or a mismatched preparation origin
cannot substitute for the declared source.

Physical orientation is explicitly `Choice.preparation_reverse`, with an explicit
row-local `PreparationOverride.preparation_reverse`. It is independent of selector
strand. A reversed digested fragment may require true; an actual-bottom PCR
frame may already produce the selected orientation and require false. Reaction
pools use their explicit native path instead of silently applying an ordered-row
reversal. No target selector itself changes chemistry, repairs strands or proves
that a preparation implements the intended sequence.

MCP keeps the same library tools. Their compact material bindings carry exact
`event` plus `MaterialSelection`; one owning workspace and the shared documentary
hydrator supply native capsules before computation. A client-supplied closed
binding is not an alternative authority form. Full current native batch records
retain the actual bound requests, targets and source evidence for replay/release.

Ordinary selected-plasmid sharing omits documentary batch/layout records while
following real native ancestry of a released product. Explicit complete-layout
publication includes every actual reference of the indivisible retained records.
Its source-closure guard attests all embedded material bindings and saved
preparation overrides, including unselected choices or diagnostic rows, before
publishing those bytes. It does not upgrade historical verdicts or rerun primer
searches to turn a diagnostic row into an accepted one.

The library overlap method requires an explicit `OverlapFinishing`: reference-only
analysis, native5′ homology processing, or native3′ annealing. Its policy is retained
in resolved recipes, preview identity, batch capture and release; it is never
silently omitted. In-Fusion's annealing route requires a documentary planned
E. coli transformation/rescue declaration. Annealed references retain separate
strands and cannot become reusable material through that declaration. Physical
comparison limits are reserved in the same shared batch work ledger. Unsupported
geometry and unfinished policy fields remain row-local errors.

The native literal acceptance uses a saved21-call top and offset4 bottom, selects
actual bottom0..10 `AATTCGTAAG`, and separately reconstructs/digests/reverses/ligates
that material. The mapped source top[15,21) occupies output[4,10); the first four
calls have no top mapping. Batch restart, release, fresh saved-run replay,
HTML/PDF, compact MCP selection and both sharing scopes have focused native fixtures. Validation is delegated to
the parent integration batch; no checks were run while authoring this patch.
The point-mismatched target `AATTCGTAAA` remains invalid; circular rotation is not
a valid negative oracle. The library slice alone does not claim that a
reference-only PCR planner can use bottom-only template calls. The integrated native
template-frame planner supplies that physics from freshly borrowed material
without fabricating stock.
