## Endpoint-aware row-band proof

For prefix indices `i in 0..=n` and `j in 0..=m`, define `delta=n-m`, `d=i-j` and radius `r>=0`. The admitted corridor is:

```
L = min(0, delta) - r
U = max(0, delta) + r
L <= i-j <= U
row_start(i) = max(0, i-U)
row_end(i)   = min(m, i-L)       // inclusive
```

Both endpoints belong to every corridor. For unequal lengths, radius zero is a corridor between endpoint diagonals, not a disconnected line. Full and corridor layouts feed the same recurrence. Absent neighbors remain `NEG`; strip edges do not create free starts, restarts or gap closure. Global boundary opening/extension costs, packed predecessor ordering and source-coordinate traceback are preserved. Transposition of longer query inputs retains Insert/Delete remapping and the symmetric proof.

Let `M=max(0,match_score,ambiguous_score,mismatch_score)` and `g=max(gap_open,gap_extend)<0`. A complete path with `P` paired steps and `G` gap calls satisfies `2P+G=n+m`. Every individual affine gap call costs at most `g`, including opposite-gap switches. To leave the corridor and return to the endpoint, a path needs at least:

```
Gmin = abs(delta) + 2*(r+1)
OffBandUpperBound = ((n+m-Gmin)/2)*M + Gmin*g
```

The escape argument is `G>=abs(d)+abs(delta-d)` for a visited omitted diagonal. Parity is exact. Increasing gap calls beyond `Gmin` further decreases this bound. If `Gmin>n+m`, no complete omitted path exists; this is represented as `NoEscapingPath`, not a numeric sentinel. Otherwise checked arithmetic yields a finite bound.

**Only selected score strictly greater than the bound excludes all off-band optima, including off-band ties.** Equality remains unproven. Full-domain evaluation and the admitted exact-symbolic identity shortcut provide their own proof. None of these proves unique correspondence within the retained domain or biological correctness. The independent mathematical review is [affine-row-band-proof-current.md](affine-row-band-proof-current.md).

## Work, memory and whole-comparison scheduling

The existing limits remain: default 16 million cumulative cells per alignment, hard 64 million, default 64 million total comparison cells and hard 128 million. The matrix payload limit remains 96 MiB and output remains at most one million columns. These are not raised to make long inputs appear supported.

`RowLayout` obtains the exact admitted cell count without allocation using checked `u128` rectangle-minus-triangle arithmetic, including on wasm32. It admits packed traceback, two sparse score rows and row offsets before allocation. Full layout uses direct rectangular indexing without an unnecessary per-row table. The previous attempt's grid is dropped before the next is allocated; only the completed path/receipt needed for fallback remains.

One borrowed ledger charges every actual evaluated/initialized DP row cell against both local and comparison limits. Wider attempts recompute cells and charge again. There is no refund or reset per band, origin or strand. Allocation/admission refusal with no evaluated cell does not count as an evaluation. Exact identity and bounded seed scans are not misrepresented as DP cells or sequencing depth.

Adaptive widening uses `min(maximum_radius,full_radius,max(r+1,2*r))`, with checked arithmetic. A strict certificate stops widening; radius/attempt/cell/memory limits retain the last completed actual path with unproven unrestricted optimality. If no attempt fits, the operation refuses. An output-column refusal never returns a truncated scientific path.

Whole comparison evaluates initial admitted bands across the bounded requested origin/strand candidates before spending widening work on unresolved contenders. Only the actual winning path, scalar candidate/attempt receipts and one active grid are retained. An actual incumbent may discharge another candidate when its score is strictly above that candidate's off-band bound: the candidate's in-band optimum is already no better than the incumbent, and omitted paths cannot beat or tie it. This does not relabel that candidate's own path as certified. Existing deterministic candidate ordering governs tied observed scores.

Candidate coverage remains independent. Large circular-reference searches nominate bounded origins from exact seeds; a better untested origin may exist. Missing candidates or unresolved proofs cannot become exhaustive comparison. Exact symbolic equality can attain a global scoring upper bound without enumerating alternative origins, but retains ambiguity/tie warnings and separate coverage flags.

## Concrete next semantic-owner design, awaiting implementation approval

The following API and limits are a bounded implementation proposal, not a claim that the semantic owner exists. It reuses the registered affine contract above.

### Exact native inputs and admission

`assess(&Workspace,&Request)` should accept two exact retained `EventBinding`s, one independently selected design and one supplied DNA consensus. Resolve both once through the existing crate-visible `material::run::resolve` after one workspace admission; this helper returns the exact immutable event molecule, not fresh material or a chemistry assertion. A later ownership move to a `Workspace` inherent resolver should update callers directly rather than introduce another event parser. Head advancement must not silently retarget a selected historical event. Missing/wrong document/event/revision is a request-binding failure, not an alignment result.

A concrete request shape is `Request { schema_version, design, consensus, comparison, consensus_axis, cds, limits }`; each CDS row is `CdsSelection { id, design_cds:AnnotationAssumption, genetic_code }`. No consensus feature is required or manufactured. DNA-only admission is an explicit first scope; the generic affine engine's RNA support does not automatically establish a long-read RNA-consensus workflow. Request policy should require global comparison; partial/local comparisons remain available in the ordinary pairwise panel but cannot satisfy this whole-consensus request.

Proposed hard bounds: 128 KiB request metadata, two selected molecules under the canonical native model guards, at most 32 CDS selections, one million alignment columns, two million aggregate selected coding calls, 512 register segments and 4096 retained changed/uncertain codon entries. The complete combined report remains bounded by the existing 32 MiB attachment limit. Coding limits should be independently configurable below these maxima and charged across all CDS rows, including overlapping selections. An exhausted coding budget retains the native sequence comparison and marks affected/unvisited coding evidence incomplete; it never converts omitted entries into absence or silently trims alignment rows. These are proposed resource policies, not biological thresholds.

One explicit coordinate-model choice is needed before circular CDS implementation: `ConsensusAxis::StoredTopology` or `DeclaredSingleCircularTurn { rationale }`. A local FASTA import is stored linear even when a user describes a whole circular plasmid. Treating its end/start as adjacent for CDS projection therefore needs an explicit computational declaration; it must not mutate the molecule's recorded topology or establish circular physical stock. Ordinary comparison already preserves the two actual topology declarations. Without that additional declaration, a coding path that requires adjacency across a linear query's stored ends is indeterminate. A design CDS crossing its own circular origin can still map wholly inside a linear query without query wrapping.

`revision(workspace,request)` binds exact events, their source revisions, current comparison settings, coordinate-model declaration, annotation/code pins and limits. The native owner computes one `alignment::review::compare` and captures the actual selected path. Fresh output uses bounded `validate_binding`/`validate_request`; explicit `validate_for` is the heavy imported-report reassessment route. No network provider lookup, saved-material replay, modified source document or implicit database operation belongs in this owner.

- The existing private [causal::Coding](../../crates/core/src/construct_qc/causal/coding.rs) demonstrates pin/code checking, native extraction and BiologicalPath consistency, but also belongs to an actual-history workflow. ### Honest path scope and literal coding scenarios

Current affine proof certifies a scoring optimum but does not enumerate in-band ties or uniquely establish biological correspondence. Therefore a nontrivial CDS comparison initially reports **conditional on the actual selected alignment path** even when its score is globally certified. Emit concrete codon/register facts under that declared path; do not turn them into native edit causes, annotation inheritance, experimental mutation calls or an overall biological pass. Unknown mapping, ambiguity or missing boundaries must remain visible, not be repaired from the design.

Independent literal fixtures for the semantic phase should include:

| Design and supplied calls under code 1 | Expected bounded statement |
| --- | --- |
| `ATGCAAGGGTAA` versus `ATGCAGGGGTAA` | Design codon1 CAA and projected CAG both encode Q. This is a path-conditional synonymous difference; retain the nucleotide substitution and source coordinates. |
| `ATGCAAGGGTAA` versus `ATGTAAGGGTAA` | Design CAA is Q; projected internal TAA is a definite stop at codon1 under the selected path/code. The existing terminal stop is not itself a newly introduced internal stop. |
| `ATGCAAGGGTAA` versus `ATGCAAGCTGGGTAA` | A selected three-base GCT insertion after CAA adds A while downstream register remains modulo zero. Do not infer cloning/edit history from this correspondence. |
| `ATGCAAGGGTAA` versus `ATGCAACGGGTAA` | A selected single inserted C yields a shifted downstream stream with one trailing base; completeness/terminal-stop evidence remains separate from register. Exact placement must come from the returned path, not the fixture's edit-intent label. |
| `ATGCAAGGGCCTAAATAG` versus `ATGCAACGGGCTAAATAG` | This intentionally exercises an alternative: a compensating insertion/deletion path and two substitutions can tie under default affine scores. Do not assert an actual transient frameshift merely from equal final length or a declared intended edit; retain the selected CIGAR and unproven uniqueness. |
| `ATGCAAGGGTAA` versus `ATGTANGGGTAA` | TAN can be stop or sense: retain unresolved/possible-stop evidence rather than a definite newly introduced stop. CAR, by contrast, can retain a definite Q amino acid while nucleotide calls remain ambiguous. |
| Reverse CDS `complement(0..12)` on `TTACCCTTGCAT`, versus `TTACCCTTACAT` | Coding order is the reverse-complement stream; the CAA-to-TAA consequence maps to original stored coordinates, not a forward substring or display-column offset. |

Further refusal/completeness fixtures should cover `/codon_start`2/3, conflicting tables, `needs_review`, exception qualifiers, repeated/fuzzy Location paths, an insertion exactly at each boundary/join, fully deleted CDS anchors, partial coding budgets and retained source-file bytes that no longer match edited current calls. ## Read validation remains a separate input contract

[trace_validation](../../crates/core/src/review/reads/trace_validation.rs) uses supported immutable trace or explicit-encoding FASTQ evidence, bounded placements and recorded native-score thresholds. Permitting alignment without qualities does not create eligible scored consensus support. It reports uncovered/conflicting/ambiguous calls, insertions and placement/optimality completeness. [Read checks](../../crates/core/src/review/reads/checks.rs) retain exact reference/read events, and [TraceValidationPanel](../../crates/web/src/reads/trace_validation.rs) opens a marked support-only consensus without copying design annotations or physical stock authority.

Do not reinterpret a provider FASTA as a fictitious scored read, fabricate Phred values, fill unknown calls from the design or label aligned-string fractions read depth. A pairwise path does not establish mixed-clone status, contamination, structural-rearrangement classes, sample identity or experimental confirmation. No new scientific tables, third-party code, raw-read pipeline or external engine is introduced by this work.
