# Editor workflow follow-up against Benchling

Reviewed 2026-11-25 using official public Benchling help and the current repository source. This is a source audit, not a local GUI acceptance test. No local browser checks, builds, application code, or authenticated Benchling session were used. It follows [the earlier editor review](BENCHLING_EDITOR_WORKFLOW_REVIEW.md), [pairwise review implementation](PAIRWISE_REVIEW.md), and [reference transfer implementation](REFERENCE_TRANSFER.md). Earlier recommendations must not be mistaken for an unchanged backlog.

Scope is desktop sequence editing and cloning design. ELN, inventory, samples, automation, organizational administration, OpenGel, mobile, further BAM/BAI work, and deferred external alignment/primer engines are excluded. Public descriptions establish interactions; they do not disclose Benchling's scientific implementation or guarantee our equivalent behavior.

## Documented interactions

- **Editing and import:** sequences can be entered manually, uploaded, or retrieved by database identifier. The documented providers include Addgene URLs and NCBI accessions. The sequence view supports insertion/deletion, annotation-preserving region transfer, display controls, topology changes, and circular reindexing. Selecting a genomic locus is a separate import route. [DNA and RNA sequence overview](https://help.benchling.com/hc/en-us/articles/39110680274189-DNA-and-RNA-sequence-overview), updated September 30, 2025.
- **Restriction discovery and digest review:** the enzyme panel supports named lists, name/site-count search, site navigation, and selection-relative filters. The guide explicitly says advanced filtering changes map visibility separately from list visibility. A digest has a fragment table, predicted gel, and a name/save action for reopening; multiple digests can appear as lanes. [View restriction enzymes](https://help.benchling.com/hc/en-us/articles/38609319462669-View-restriction-enzymes), updated October 2, 2025.
- **Annotations and translations:** the expanded feature view supports multiple selection and bulk type/strand/color changes. Hiding differs from deletion. A selected region can become a named translation with strand and genetic code; translation regions can be grouped, analyzed, and used to create a protein sequence. [Annotations and translations](https://help.benchling.com/hc/en-us/articles/39768268305805-How-to-characterize-sequences-with-annotations-and-translations), updated September 30, 2025.
- **Comparison:** saved alignments reopen from their participating sequences. Review supports mismatch arrows, search, annotation/translation visibility, trimming, explicit realignment, and FASTA/Clustal/PDF export. Circular alignment presentation can change without editing stored DNA. Its external alignment engines are outside our runtime scope. [How to create alignments](https://help.benchling.com/hc/en-us/articles/39922093033869-How-to-create-alignments), updated July 21, 2026.
- **Saved design provenance:** assembled constructs expose visual assembly history from the resulting sequence. It is separate from the generic lineage sidebar. [Assembly tool guide](https://help.benchling.com/hc/en-us/articles/39922419457165-How-to-use-the-combinatorial-cloning-and-concatenation-assembly-tools) and [Assembly History location](https://help.benchling.com/hc/en-us/articles/17806823063053-Why-can-I-no-longer-see-the-assembly-history-in-the-lineage-tab).

## Remaining actionable connections

The following are recommendations inferred by comparing those documented interactions with source. They are not statements about Benchling internals.

1. **Annotation management in one list.** The current `app.rs` annotation panel selects one feature, and `FeatureEditor` edits one feature with generic location/qualifier fields. Add an expanded selectable table, dedicated strand/color controls, and batch type/strand/color edits. Add visibility preferences independent of deletion and scientific history. Preserve qualifier multiplicity, compound/fuzzy locations, and review flags; commit scientific batch changes once against the originating event. Existing library/import proposal multi-selection does not implement editing existing annotations in bulk.

2. **Finish translation outputs and circular ORF selection.** `BiologyPanel` computes a frame over the whole reference or translates a selected CDS, annotates ORFs, and downloads proteins. Its frame action currently sends the entire molecule, so arbitrary selected-region translation must be connected explicitly before adding retain-as-CDS or linked-protein actions. Connect those outputs to the existing feature/history model with explicit code, orientation, initiation policy, and exact source event. Its current “Select ORF” action highlights only the first span of compound results and discloses that limitation; make the complete footprint inspectable. Keep unsupported codes explicit: the audited native set is currently 1, 2, and 11. Additional codes are independent data/algorithm work, not a UI dropdown change.

3. **Saved digest setups and a direct gel route.** `digest.rs` already reconstructs fragments, displays their ends, navigates to source, opens derived products with provenance, and sends fragments to assembly. `gel.rs` already predicts multiple lanes and ranks diagnostic digests. What is missing is the connecting workflow: name/save/reopen a digest setup on its exact source event and send that existing setup to a predicted gel without re-entering enzyme names. Retained fragment producer recipes are not a named digest collection. Reopening must remain historical until explicit recomputation; preserve catalog geometry, source events, methylation assumptions, and chemistry rather than treating an enzyme list as the full digest.

4. **Comparison context and portable review output.** Keep the implemented mismatch queue, complete paging, and event-bound saving. The ordinary pairwise viewer presently exports JSON and renders aligned bases/differences, without sequence search or mapped feature/translation overlays. Add those as views over the existing native alignment coordinate mappings. Offer aligned FASTA/Clustal and printable HTML/PDF directly from this retained comparison, reusing existing format/report primitives. The separate imported-alignment viewer's exports do not make these outputs reachable from a computed pairwise report. Export must distinguish displayed orientation from native source coordinates and historical from freshly computed evidence.

5. **Improve the entry to existing provenance.** Saved run details already expose exact inputs, target, products, operation descriptions, and replay. A compact source → preparation → assembly → product overview can make that existing record easier to scan from the product. Treat this as a presentation connection, not missing scientific lineage. The reviewed Benchling documents do not establish immutable-event replay or independent target verification; those remain our own requirements.

The first three connections are the highest-value editor follow-ups. Broader gene-symbol/provider discovery and genomic-locus import are later source expansion, not evidence that the requested Addgene/NCBI import is absent. Final GUI acceptance, interaction smoothness, and layout review remain deferred under the user's instruction; this audit did not perform them.
