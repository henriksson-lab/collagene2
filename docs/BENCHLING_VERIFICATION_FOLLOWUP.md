# Verification, conflicting evidence and output continuity: follow-up

Reviewed 2026-11-25 against public official Benchling documentation and the current repository contracts. Read the existing Benchling verification/history/editor/output reviews and [cloning interaction design](CLONING_INTERACTION_DESIGN.md) first. This records unresolved questions, not a replacement feature backlog. Saved event-bound checks, explicit review decisions, comparison exports, producing-run navigation and atomic output/archive release already have implementations. No compiler, application browser check or scientific code was used.

## What the follow-up establishes

**Read evidence is not an automatic reference correction.** The current alignment guide separates template comparison from creating a new consensus. It documents trace/quality/vote visibility, region comments, trimming and explicit realignment after edited inputs or changed trims. Its text does not define an accept-conflicting-call transaction or imply that comments approve evidence. Trimmed calls are ignored on realignment, so changing trim controls is a change to the computation's inputs, rather than merely hiding rows. [How to create alignments, updated 2026-07-21](https://help.benchling.com/hc/en-us/articles/39922093033869-How-to-create-alignments).

The older teaching exercise describes consensus as the most frequent nucleotide per aligned position and uses an independently copied vector to reconstruct an unknown insert. It does not specify tie handling, uncovered positions, quality weighting, duplicate-read dependence or thresholds sufficient to label an entire clone verified. Its educational verification wording should not become a whole-plasmid acceptance rule. [DNA Sequencing, updated 2022-10-13](https://help.benchling.com/hc/en-us/articles/9684245367821-DNA-Sequencing).

**A saved assembly and an experimentally checked clone remain different objects.** Current assembly help says finalization locks the design modal and generates constructs plus optional primers/fragments; the assembly object remains available afterward. The resulting sequence exposes Assembly History. It does not document a conflict-resolution workflow for later Sanger reads, automatic propagation of a corrected reference back into the original design, or editing a finalized assembly in place. These remain unknown, rather than claimed absent. [Combinatorial assembly guide, updated 2025-12-12](https://help.benchling.com/hc/en-us/articles/39922419457165-How-to-use-the-combinatorial-cloning-and-concatenation-assembly-tools).

**Portable review and experimental instructions need separate labels.** Current help lists alignment exports as FASTA, Clustal, screen-capture PDF and formatted PDF. That establishes two presentation exports, not preservation of chromatogram channels, exact review decisions or the full assembly graph. The old Golden Gate announcement documents printable assembly summaries and primer export; no reviewed current guide specifies generated wet-laboratory HTML/PDF instructions with reagent quantities or validated conditions. [Alignment export instructions](https://help.benchling.com/hc/en-us/articles/39922093033869-How-to-create-alignments), [historical Golden Gate announcement, 2014-12-16](https://www.benchling.com/blog/golden-gate-assembly-wizard).

## Implementation implications — preserve existing contracts

- Keep [read checks](READ_CHECKS.md) and [human review](READ_REVIEW.md) distinct. Uncovered calls remain unsupported; retaining the reference or choosing one conflicting eligible observation must not relabel the other evidence agreement. A derived reference needs a new check. No public Benchling evidence justifies weakening these existing rules or replacing them with majority vote.
- Keep product → producing run/design and product → sequencing checks as related, separate entry points. Our [run navigation](RUN_LINEAGE_UI.md) and [atomic release](COMBINATORIAL_RELEASE.md) already supply the foundations. A changed checked reference should retain its parent design rather than silently rewrite an earlier finalized product or grant it a new positive status.
- Continue exporting the frozen reviewed plan's actual oligos and computed steps, and preserve native events/manifests for full recovery. Alignment PDFs, sequencing-review evidence, cloning protocols and sequence-exchange files serve different purposes. Our fresh native protocol reconstruction and explicit unspecified conditions are project requirements, not demonstrated Benchling parity.

The follow-up found no documented alternative to our conflict/uncovered-evidence policy and no new missing scientific engine. Remaining unknowns are Benchling's detailed consensus arbitration, partial-coverage acceptance policy, immutable evidence/version semantics after realignment, post-finalization correction propagation and full protocol/graph export fidelity. Do not infer these from a green assembly readiness status, visible vote counts or educational “verified” wording. Final GUI continuity and usability acceptance remain deferred under the user's instruction.
