# Run and Derived material origins

`MaterialSelection::{Run, Derived}` selects a retained targeted-run product or an exact target-free derived product event. `MaterialOrigin` carries its closed native recipe capsule. Run preserves an independently targeted cloning workflow; Derived preserves processing such as exact PCR or catalog digestion. Both are current, distinct source contracts.

Origin discovery lists choices without silently selecting one. An explicit choice must match the actual event and its retained ownership. Workspace attestation checks document/event/revision identities, original snapshots, owning runs and canonical derivation records. Equal sequence content and descriptive labels cannot replace these bindings.

`Preparation::FromRun` and `FromDerived` reconstruct private native material before applying the declared flat child preparation. Their input-only reconstruction steps retain actual strands, offsets, termini, modifications, nicks and inherited incomplete evidence. The enclosing assembly still has its own independent intended target.

One iterative ancestry walker and aggregate ledger serve Run and Derived roots and descendants. Wrappers and source models are charged before opaque candidate/record decoding or rich cloning. Depth, bytes, bases, steps and model bounds are shared across all roots; a nested record cannot reset its allowance. Only current candidate, plan and worker encodings are accepted.

Recorded scientific assessments remain documentary. Current native replay must establish material before reuse; a serialized summary is never restored as authority. Protocol generation and saved-run review require fresh verification against the retained independent target.

Fixtures exercise PCR → catalog digest → PCR/assembly, actual unequal strand geometry, modification ancestry, incomplete sources, archive/publication replay, exact-event ownership and aggregate resource exhaustion.
