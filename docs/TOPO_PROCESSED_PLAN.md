# Retained processed-TOPO cloning plans

`Operation::ProcessedTopo` binds original source roles to a literal preparation,
transfer, ligase-treatment and contour-selection request. It accepts no alleged
product graph or trusted imported duplex. Fresh verification reconstructs that
request once and retains its complete typed report in `processed_step_reports`.

A faithfully bridged result supplies private tracked material to subsequent native
steps. Restriction digestion uses the actual top/bottom, nicks, ends and Unknown
internal modification state; a portable sequence document never substitutes for
that material. An independent fixture seals a21bp TA construct then cuts its actual
EcoRI site, checking literal target DNA and AATT overhangs.

The independent target remains separate from component, origin and reaction
selection. The operation produces material under its explicit preparation and
proof options; it does not reuse old `CheckedTopo` acceptance or infer isolation.
Other components, blocked/unknown operations and retained nicks remain visible.
A withheld contour keeps full typed evidence and returns Incomplete without
inventing a product. A separately wrong target remains Invalid.

The initial processed preparation accepts original Input sources. Using Step
material as a new processed preparation is explicitly unsupported until its
tracked modification ancestry is mapped. This does not prevent a fresh processed
result from feeding a later digest through the private material vector. Incoming
portable physical/reference-only summaries cannot restore lost physical state.

## Review and outputs

The processed-contour panel offers an explicit **Open processed candidate for
verification** action for a current faithful bridge. It passes declarations,
not proof, to the parent. Exact source events, independent target event, workspace
epoch, inspected orientation and request context are rechecked before opening an
advisory candidate. The existing Verify, stage, atomic finalization and retained
run route performs fresh reconstruction and preserves original event ancestry.

HTML/PDF protocols include actual preparation/ordered PCR oligos, ligase
assumption, selected nick pairs, component/source seed/options and scientific
limitations. PDFs use readable steps and evidence summaries/context hashes;
large graph arrays remain in matching full JSON evidence. Embedded TOPO primers
remain explicitly unavailable in the general primer-order extraction profile.
MCP `verify_plan` returns the full typed processed evidence as a bounded artifact.

## Historical graphs and fresh authority

A newly retained processed run atomically stores a separate immutable
`processed-topo-run-evidence-v1` JSON attachment alongside its unchanged RunRecord.
It binds run/plan/recorded-engine and exact source/target/product events to all
processed step graphs. Duplicate, missing, orphaned or transplanted attachments
fail structural validation. Workspace archives keep the full original and treated
graphs, including displaced material, pairing and released activation.

Historical inspection checks documentary bindings and bounds, not current chemical
rules. Older inner algorithm labels remain inspectable after engine changes.
Fresh replay reconstructs current evidence; neither the attachment nor imported
status can populate private material state. The GUI downloads exact attachment
bytes through worker149, with cancellation/workspace/run guards and no main-thread
JSON parsing/serialization. Older runs without attachments remain explicit.
MCP `inspect_workspace_run_evidence` provides the same historical boundary.

## Compatible formats

The appended operation is ordinal19. Worker65, candidate13, workspace plan11 and
science16 introduce its current interfaces and typed evidence. Existing operation
ordinals and StepReport layout stay unchanged. VerificationReport appends a
separate processed-evidence vector.

Nine old positional wire paths have explicit <=64 converters: Verification,
InversePcr, RunReplay, OverlapRecipePreview, LigationRecipePreview,
AssemblyJunctionInspection, PreparedGoldenGatePool, GoldenGateReaction and
DomesticationPrepared. Historical fields/engines are preserved, with an empty new
vector. Earlier1–26 bare-report migration still runs first. JSON defaults alone
are not used as a Postcard migration. Old headers reject the new operation,
science/evidence and historical-download selectors; ordinary old files remain
readable. Historical RunRecord and RunReceipt layouts remain unchanged.

Directional-flap processing is now available through [ordered actions](TOPO_PROCESSING_ACTIONS.md). Broader upstream tracked-source chemistry,
durable graph-only review without a material product, remaining cloning methods
and final delivery/GUI acceptance remain active requirements.
