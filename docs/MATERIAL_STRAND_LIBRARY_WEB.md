# Actual-strand library contributions and primer preparation

An assembly contribution's source strand and its physical preparation orientation are separate declarations. A saved material contribution can select stored bottom-strand coordinates beyond the displayed top reference. Its original source event, selected native origin and state revision remain pinned. The reference viewer receives only genuine mapped top spans; bottom-only calls remain visible in the actual contribution and native template evidence without invented map coordinates.

The current draft stores a required-nullable `Slot.material_origin`. It belongs to the contribution, independently of the active preparation. A physical preparation must agree with that declared source origin. Source replacement clears the pin; an existing actual-strand selector cannot silently acquire another origin. Library choices retain the selector and source origin through switching, persistence, bin reordering and recovery. Native designs receive one exact-event material-binding roster. Physical reversal is explicit in each construct's preparation override.

The source-stage picker selects the retained Run or Derived origin. For material contributions, **Reverse source contribution** changes which original strand/range defines intended DNA. **Reverse prepared fragment** independently declares the reaction product's assembly orientation. Selecting an actual bottom contribution does not implicitly reverse its later PCR product.

## Primer frames and explicit proposals

Exact PCR declarations and the two initial overlap-extension PCR branches carry a required template strand. New original-source declarations explicitly use Top. A saved source can explicitly use Bottom, with coordinates in that real strand's stored 5′→3′ frame. Outer PCR after extension uses the newly synthesized product's Top frame. Native execution examines the whole source rather than cropping to the intended contribution; competing geometries, nicked templates and unsupported coverage remain diagnostics.

The existing **Propose primers for this construct** action is available for actual-strand intent even without an internal edit. It uses the same whole-construct planner as substitutions and indels. A returned proposal retains its native frame and explicit prepared reversal. Applying changes physical preparation settings for the active construct, while leaving its selector, source origin and independent intended DNA unchanged. Native source-frame sequences and actual primer-search notes are shown separately from the whole-recipe verification status. Source-frame evidence is documentary and cannot create a reusable stock.

Explicit user tails are preserved: saved-source homology/tail determination runs in the native worker, and returned tails are checked before accepting or applying a proposal. Changing source event, origin, selector, settings, construct or workspace invalidates pending results. Applying a proposal does not accept physical material; the ordinary recipe must still be freshly verified and its selected outputs saved through the existing acknowledged transaction.

## Bounded rendering and current limits

Reactive batch identity uses the same raw declaration revision as explicit projection. Source bodies are represented by immutable captured revisions and origin hashes computed once at capture/decoding. Raw edits, frames, reversal and unfinished settings remain part of the guard. Native capsule copying and full workspace attestation occur during explicit preparation; rendering neither rebuilds closed origins nor replays scientific history.

The standalone ordinary PCR viewer remains explicitly Top-frame in this slice. The single-contribution OE proposal keeps its reference-range guard. The standalone PCR-product digest picker still lacks a generic Derived-source interface and presents that limitation explicitly; it does not flatten a saved source. Whole-construct primer preparation and library compilation support the native Run and Derived routes.
