# GFF3 and BED annotation exchange

The independent `annotation_formats` adapter imports coordinate annotations onto an explicitly selected nucleotide reference. It does not open a genome by guessing chromosome names, fetch remote references, execute browser/track directives, or establish the correctness of an annotation.

The coordinate conventions follow the [Sequence Ontology GFF3 specification](https://github.com/The-Sequence-Ontology/Specifications/blob/master/gff3.md) and the [UCSC BED specification](https://genome.ucsc.edu/FAQ/FAQformat.html#format1): GFF3 uses one-based closed coordinates; BED uses zero-based half-open intervals. The internal model uses zero-based half-open intervals. These coordinate systems are converted explicitly, including reverse-strand compound locations.

## Bound import and evidence

`import_annotations(reference, text, format, seqid)` requires the exact sequence ID to map to the supplied DNA/RNA reference. Other sequence IDs remain in the original input and are listed as skipped; their coordinates are not silently moved onto the selected sequence. The report binds the complete current document revision, original bytes/hash, mapping, source line numbers, proposals and diagnostics. `validate(reference)` rederives the report from the original source and mapping. Changed proposals, warnings, source evidence and stale references fail validation.

`apply_annotations(reference, report, selected_indices)` appends only explicitly selected proposals. It neither replaces existing annotations nor silently duplicates an already present identical feature. All selections and the source report are checked before a result is returned. Every imported feature requires review. Raw source is retained once under its content hash in document metadata, with separate application/selection provenance. Native workspace deduplication preserves that evidence across revision history.

Unstranded and unknown-strand intervals retain their coordinate spans in `Location::Order`, which disables exact biological extraction. Point/between-base sites are retained as unresolved source evidence instead of inventing a base interval. GFF3 single-base intervals for known interval types (including gene, CDS, exon, SNP and SNV) use ordinary one-based inclusive coordinates. Equal-coordinate point-site types such as insertion_site and unrecognized types remain unresolved rather than assuming whether they denote a base or a boundary.

## GFF3 profile

Requires `##gff-version 3`, nine tab-separated fields, valid UTF-8/percent escapes, finite scores, explicit CDS phases and bounded positive coordinates. IDs group discontinuous rows; Parent relationships are validated for missing IDs and cycles. Multiple parents and multivalued attributes remain distinct. Source strings, scores, attributes and per-row CDS phases are retained, rather than being flattened into one invented record. Unknown ontology terms are preserved without claiming ontology validation; Target/Gap remain alignment evidence rather than a reconstructed alignment.

Consistent phased CDS parts yield an explicit initial `codon_start` counted in biological strand order. Inconsistent phases retain diagnostics and source phases, with no current codon-start/translation assertion. A single circular-origin row with end beyond the reference length becomes an exact origin-spanning location, restricted to one turn and an explicitly circular reference. Circular compound anchors requiring inference remain unresolved. One ID spanning different reference IDs/types/strands is unsupported. Embedded FASTA is parsed, and a matching selected sequence must agree exactly with the supplied reference. No remote sequence is downloaded.

## BED profile

Imports BED3–BED9 and complete BED12, with consistent field widths within each track. BED10/11, bedDetail and other extensions are unsupported. BED12 blocks must be positive, nonoverlapping, agree with their count, start at chromStart and end at chromEnd. Strand, score, color and thick coordinates are validated. Thick regions remain display evidence; they do not imply CDS type or reading phase. Track/browser lines and exact original row bytes remain source evidence.

## Current export and loss policy

`export_annotations(reference, format, seqid)` returns text plus explicit warnings. GFF3 preserves unchanged imported row attributes, score, Parent hierarchy and per-part phases. A selected child whose Parent is absent cannot be exported as a fabricated complete hierarchy. Generic CDS export requires one explicit valid `codon_start`; it never guesses phase. Common explicit types (`gene`, `CDS`, `mRNA`, `exon`, `promoter`, `terminator`, `sequence_feature`) are retained; other generic input kinds use `sequence_feature` plus `cg2_original_type` and a loss warning instead of inventing ontology equivalence. The [INSDC regulatory vocabulary](https://www.insdc.org/submitting-standards/controlled-vocabulary-regulatoryclass/) and [SO terminator term](https://sequenceontology.org/browser/current_release/term/SO%3A0000141/) document the two regulatory names. Generic exact single-base intervals export with an interval type; unsupported generic kinds use sequence_feature with an explicit original-type/loss report. Unknown/fuzzy/mixed-order locations are not flattened. BED writes a consistent BED12 profile; ordinary features lose type/qualifiers/phase with warnings. Missing score/color and no-thick extents use documented display placeholders, not measured scores or coding predictions. Circular-origin features cannot be flattened into BED blocks.

Imported source-record evidence binds original kind, geometry and qualifiers. Export reconstructs that geometry/phase from retained rows; stale evidence after editing, reversal, origin changes or qualifier edits is rejected. Original-source download remains available. This guard prevents replaying old source coordinates as current annotations; it is an integrity check, not authentication or scientific verification. The original annotation source can also be downloaded byte-for-byte through `report.original_bytes()`.

Limits are 8 MiB input, 64 KiB lines, 10,000 records, 20,000 retained directives/comments, 50,000 BED parts, 32 MiB serialized reports/exports and the standard document/native payload limits. Integer overflow, malformed escapes and inconsistent record geometry fail explicitly. The implementation uses no external program or new dependency.

Tests use literal GFF3/BED fixtures, explicit phase/origin/strand expectations, tampered report/evidence cases and an independent 1,104-case substring/complement coordinate oracle. They exercise exact source/JSON/native retention, missing/cyclic parents, stale imports/exports, embedded FASTA disagreements, point/unknown-strand safeguards and malformed block boundaries.

The web Annotation files panel accepts pasted text or a selected file, requires the exact reference sequence ID, and paginates proposals for explicit application. GFF/BED files opened through the main file chooser route to this review panel. Original inputs remain downloadable from retained document metadata even after edits or reopening; the source hash is rechecked before download. Interactive circular maps and SVG exports share the rule for biological terminal arrows, suppressing direction for unordered/unknown-strand locations.
