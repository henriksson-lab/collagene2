# Unsigned desktop package builds

Run the **Desktop packages (unsigned)** workflow manually from GitHub Actions. Choose `development` for fast iteration or `release` for an optimized delivery candidate. Both paths produce installers/application bundles; neither publishes a GitHub release or requires signing credentials. The separate automatic desktop build and scientific workflows are unchanged.

The workflow builds a fresh bounded Leptos frontend and current worker once on Linux, then passes that exact artifact to three independent native jobs. Native jobs select only their host architecture; this is not a universal macOS build or an ARM Windows/Linux matrix. The artifact metadata records the actual architecture and source commit.

| Runner | Expected output | Headless payload check |
| --- | --- | --- |
| Ubuntu 22.04 x64 | AppImage and Debian `.deb` | Extract `.deb` without installing, run its actual executable with `--mcp` |
| Windows hosted x64 | NSIS `-setup.exe` installer | Run the exact native executable supplied to NSIS with `--mcp`; do not run the installer |
| macOS hosted architecture | `.app` in a permission-preserving tar archive, plus `.dmg` | Run the actual `.app/Contents/MacOS` executable with `--mcp` |

The existing smoke script initializes MCP and verifies a virtual restriction digest over stdio. It does not open a WebView, browser, application listener, or credential vault. A release dispatch runs this same check against the release executable, including Windows. Package creation and headless checks have not been executed locally as part of adding the workflow; the first successful hosted run is still required evidence.

The workflow downloads **cargo-tauri 2.11.3** directly from the [official Tauri release assets](https://github.com/tauri-apps/tauri/releases/tag/tauri-cli-v2.11.3). Platform archive names and SHA256 digests are pinned in the workflow; download/extraction are size-bounded and only the expected executable is written. Missing binaries or checksum mismatches fail without a Cargo CLI compilation fallback. No Node/npm/TypeScript build tooling is needed. Trunk 0.21.14 and wasm-bindgen-cli 0.2.128 remain pinned prebuilt tools. Native Cargo dependencies remain locked; release uses the repository's release profile, while development uses the existing debug-information-disabled development profile and two-job limit.

`tauri.conf.json` keeps `bundle.active=false`. The [pinned CLI source](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.3/crates/tauri-cli/src/build.rs) explicitly bundles when `--bundles` is supplied even with that setting, so plain `cargo build` stays a build-only operation. The packaging command adds `--ci --no-sign --config tauri.package.conf.json` and explicit platform bundle formats; `--debug` is added only for development. The overlay changes package descriptions/category and embeds the WebView2 **offline installer** on Windows. The [official Windows installer guide](https://v2.tauri.app/distribute/windows-installer/#offline-installer) explains that this larger payload supports installing WebView2 without an internet connection. CI itself downloads SDK/bundler resources; offline application operation does not mean offline CI.

PNG/ICO icons remain the current provisional application artwork. A macOS ICNS container preserves the existing 64px RGBA PNG unchanged. Packaging runs the pinned CLI's `icon` command before compilation to produce all platform layers, including recommended ICO/ICNS sizes, from that same source. This supplies valid format layers, not higher-resolution artwork. The [official icon guide](https://v2.tauri.app/develop/icons/) documents the platform formats and generated layers. Final branding can replace the source icon later.

Linux uses Ubuntu 22.04 as its initial native packaging baseline and installs Tauri's native development packages plus packaging tools on the hosted runner only. [Tauri's Debian](https://v2.tauri.app/distribute/debian/#limitations) and [AppImage](https://v2.tauri.app/distribute/appimage/#limitations) guides explain why builds from a newer glibc baseline may not run on older distributions. A `.deb` still requires the operating system's declared runtime packages; an AppImage does not establish compatibility with every Linux distribution. AppImage tooling, NSIS, DMG creation, and the WebView2 payload are build-time packaging tools, not external scientific programs used by Collagene.

Download `desktop-packages-unsigned-<runner>-<profile>-<commit>` artifacts from the completed run. They expire after seven days and contain only the expected package formats and `BUILD.json`, with per-file SHA256 hashes. Outputs are bounded to 1 GiB per package and 2 GiB total per platform. The macOS application is tarred before upload to preserve executable permissions and symlinks; DMG/installer files are retained as files. No release, updater manifest, signing secret, or remote credential is created.

These are unsigned prerelease artifacts. Windows reputation prompts, macOS Gatekeeper/notarization, installer install/uninstall behavior, WebView operation, native credential-store acceptance, offline restart persistence, and real-machine GUI acceptance remain separate delivery checks. Successful packaging and MCP checks alone do not establish those properties. Do not describe this workflow as a signed or production release pipeline.

The first hosted package run for `3020c0a` compiled the native binary on all three platforms, then rejected the unsupported `Science` bundle category. The overlay now uses `Education`, listed by the [official configuration reference](https://v2.tauri.app/reference/config/#category). A fresh successful package run is still required; compiled binaries alone do not establish installer delivery.
