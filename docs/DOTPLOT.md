# Source-bound window dot plots

`dotplot::analyze(reference, query, options)` is an independently implemented, embedded Rust window comparison (`dotplot-1`), shared by native and WASM callers. It does not call another aligner or cloning application. The conceptual dot-matrix interpretation follows the [NCBI-hosted Retroviruses text](https://www.ncbi.nlm.nih.gov/books/NBK19466/?report=reader): repeated or inverted sequence regions can form additional diagonal patterns. This implementation is its own precisely defined window profile, not BLAST, a gapped alignment, an assembly algorithm or a test of evolutionary homology.

## Windows and coordinates

Both sources must declare the same DNA, RNA or Protein alphabet. A window is 1–1,024 residues/bases and cannot exceed either source length, even for a circular record. Every candidate compares aligned residues in a fixed-size, ungapped window. `min_matches` is an integer count of compatible positions, from one to the window length. It is not a percent similarity or a gapped alignment score.

Nucleotide symbols use their IUPAC base sets. Protein B means D/N, Z means E/Q, J means I/L and X means any of the 22 modeled amino-acid symbols, including U/O; stop `*` is a separate singleton. A position is compatible if its two symbol sets intersect. It is certain only when both sets are singletons and equal. Thus R/R, B/B and X/X never become definite identity. `compatible_matches` includes certain matches. `certain_matches` counts definite identities. A hit's `certain` flag means the configured threshold is met by definite identities alone; it does not assert that every residue in a lower-threshold window is identical.

Nucleotide comparison optionally includes the reverse complement of the query. Protein comparison is forward-only and rejects an enabled reverse-complement option. Palindromic queries retain both orientation records because their coordinate mappings differ. RNA uses U/A complementarity.

`reference_start` is the original reference coordinate of the first aligned residue. `query_start` is the original query coordinate aligned with that reference residue: it increases through a forward window and decreases through a reverse window. Each hit retains ascending half-open `reference_spans` and `query_spans` in biological traversal order. To extract a reverse query window, reverse-complement each listed span and join them in their listed order. Crossing an origin splits a window into two spans; a window never makes multiple laps. The effective `reference_circular` / `query_circular` flags require both circular source topology and `wrap_circular`. Disabling that option compares the stored linearized origins and explicitly omits crossing-origin windows.

The interactive view may draw each tested hit's start as an anchor. SVG exports draw the complete window segment, split whenever either coordinate crosses its origin. A segment is a visual summary of a qualifying window; with a lower threshold it does not mean every base along the segment matched. Full window counts/spans remain available for inspection and JSON export. Standalone SVG metadata also retains the exact engine, source/query revisions, options and options revision, coordinate domains, work and completion/sampling flags. These are unverified producer declarations; importing the figure never grants verification authority.

## Exact indexing, ambiguity and sampling

When both complete sequences contain only singleton symbols and the threshold equals the full window length, an exact-word index selects candidate pairs. A deterministic noncryptographic word fingerprint accelerates lookup, but every matching bucket is checked against its actual complete window. Hash collisions cannot create reported matches. Every repeated reference word position is retained; no minimizer, best-hit rule or arbitrary per-word frequency cutoff silently removes repeats. A different fingerprint proves nonidentity for the concrete word. The report accounts for these exclusions in `examined_windows`.

Any unresolved source symbol or a lower identity threshold selects a direct exhaustive window-grid scan with set comparisons. It does not silently seed only the concrete subset or treat ambiguous windows as absent. This more general strategy can require quadratic work and may need a larger stride or work budget for long inputs. Work exhaustion is an incomplete result, never a negative search conclusion.

Stride 1 tests all eligible starts. A larger stride tests starts 0, stride, 2×stride, … in the forward reference and in each oriented query. Consequently reverse-query start coordinates are mapped back from that oriented grid rather than rounded to the original forward-query grid. `sampled` is true whenever stride exceeds one. `grid_complete` means all windows on that declared grid were classified and every qualifying hit was retained. `complete` requires both `grid_complete` and an unsampled grid. An output cap can therefore clear these flags even when `examined_windows == total_windows`: classification alone does not make the retained result exhaustive. A complete sampled-grid search never claims full-domain exhaustiveness. `total_windows` counts all declared grid pairs and orientations; `examined_windows` counts windows fully classified as matches or exclusions. An unfinished indexed bucket contributes only classified candidates plus fingerprint exclusions.

## Resource bounds and interpretation

Defaults are a 15-residue exact window, stride 1, both nucleotide strands, circular wrapping, 20,000,000 work units, 100,000 hits and 1,000,000 reference index entries. Hard work is 200,000,000 units; hit and index-entry limits cannot exceed those defaults. Each source is bounded to 10,000,000 sequence symbols and 16 MiB of conservatively serialized source evidence before hashing. Features/location nodes, metadata and location nesting have additional hard limits. Index storage has a conservative 96 MiB budget, and report JSON and SVG each have a 16 MiB output bound. Output budget accounting includes every retained hit and reserves envelope space; reaching any budget is explicit.

Work units count word-fingerprint residues and actual residue comparisons, not CPU cycles. Index lookup and final deterministic ordering have separate finite source/index/hit limits. The general scan can terminate a window early only when its remaining residues cannot meet the threshold. Index construction must finish before its index is used: a truncated reference index is never treated as evidence that unindexed matches are absent. Limits stop the scan rather than silently dropping frequent words. Large, dense self-plots may require a larger stride; this remains visibly sampled, and all retained exact hit coordinates are inspectable.

Reports bind both complete molecular revisions, options revision, engine identity, source alphabet/length/topology and effective circular behavior. Report validators check structural/coordinate consistency. `validate_bindings_for` additionally checks exact submitted sources and options without repeating the potentially expensive dot-plot search. These are integrity/binding checks, not authentication of an external producer's claimed hits or exhaustiveness. Fresh trusted computation is required for correctness. Neither a diagonal nor an empty/truncated plot establishes physical identity, cloning verification, read coverage, a unique alignment or common ancestry.

The scientific core adds no physical operation and changes neither the cloning verifier nor candidate/workspace-plan semantics. Dot plots complement pairwise alignment; de novo Sanger contig assembly remains a separate F24 capability.
