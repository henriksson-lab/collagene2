# Current DOM, HTML and SVG boundary review

Date: 2026-11-28. Source-only review of the working tree; concurrent changes may supersede individual locations. No browser, application HTTP, network probing, compiler or test execution was performed. This is a finite review, not a security certification.

## Result

No confirmed exploitable DOM/HTML/SVG injection was established in the inspected paths. No production patch is proposed from this review. Findings in resource decoding, search work bounds, authentication and hosted MCP lifecycle belong to the other parallel reviews.

## Inspected boundaries and evidence

| Boundary | Source evidence and conclusion |
| --- | --- |
| Live raw markup | The production `inner_html` search in `crates/web` and `crates/core` identifies the gel view at `crates/web/src/restriction/gel.rs:621`. It consumes `collagene_core::output::gel::render_svg`, rather than an uploaded SVG. `crates/core/src/output/gel.rs:678` escapes ampersands, angle brackets and both quote characters. The writer applies it to lane labels, source revisions, preparation strings and JSON metadata. Numeric geometry is produced from validated calibration/lane values. The inspected path does not permit a document label to close a text/metadata node or introduce an active attribute. |
| Protocol HTML | `crates/core/src/verification/output.rs:11` provides five-character HTML escaping. The checked protocol writer escapes plan/target/input names, input identifiers, serialized policies, findings, assumptions, evidence notes, quantities and provenance. Its embedded map is generated by the map SVG writer. Raw TOPO debug fields at lines290–299 were traced into `crates/topo/src/lib.rs`: `SourcePlacement` and `Call` contain numeric coordinates, and `FivePrime` is a closed unit enum. The string-bearing three-prime/chain-end diagnostics are escaped. These apparent raw debug sinks did not establish an injection. |
| Map SVG | `crates/core/src/output/svg.rs:142` escapes XML text/attributes and replaces XML-invalid control scalars. Labels, descriptions and metadata pass through this writer; uploaded SVG is not the map renderer input. Map shape/style constants and generated identifiers are not imported markup. |
| Other report HTML | `crates/core/src/output/layout.rs:688` and `crates/core/src/output/quantities.rs:1009` escape free text. Inspected HTML branches escape document/well labels, source names/identities, warnings, serialized targets and paragraph content. Raw layout/context/declaration revisions are content digests rather than free-form display fields. `crates/core/src/alignment/export.rs:318` writes escaped review text to its HTML output. |
| PNG conversion | `crates/core/src/output/raster.rs:248` is a private generated-SVG conversion boundary. Parsing disables DTD resolution, limits XML nodes, rejects `image`, `script`, `foreignObject` and `style`, and rejects nonfragment `href`/`src`. Resvg image resolvers are disabled and a bundled font is used. These restrictions are additional to generated-only callers; they are not permission to render arbitrary uploaded SVG in the application. |
| Citation links | Dynamic anchors are present in restriction, methylation, CRISPR, multisite and ligation-profile views. Enzyme catalog import validates sources before constructing `Catalog` (`crates/enzyme-catalog/src/lib.rs:229,459`), including an `https://` prefix. Imported multisite profiles call `Profile::validate` before display (`crates/web/src/assembly/draft/assembly_multisite_view.rs:53–56,82–84`); `crates/recombination/src/multisite.rs:43–46` requires HTTPS source/map URLs. CRISPR and methylation sources have corresponding HTTPS admission or built-in literal sources. The ligation ranking selector displays bundled published profiles. Anchors use `target="_blank"` with `rel="noopener noreferrer"`. No reachable imported `javascript:` citation was established. |
| Download links | `crates/web/src/io/download.rs:150` creates an object URL from bytes, assigns the generated URL and filename through DOM attribute setters, clicks a download anchor, then revokes the URL. Filenames do not become markup or executable JavaScript. Standalone exported HTML still depends on its writers escaping correctly; download semantics alone do not establish safety. |
| JavaScript/native bridge | The inspected JS function casts in `crates/web/src/platform/desktop_rpc.rs` and `crates/web/src/io/source_gateway_client.rs` obtain existing Tauri/crypto functions and pass typed strings or binary arrays. They do not compile user text. WebMCP's inline JavaScript in `crates/web/src/ai/web_mcp.rs` is a static source literal and passes arguments/results through JSON serialization; it does not interpolate imported strings into executable source. Tauri capability `crates/desktop/capabilities/main-local.json` is restricted to the local main window, with no remote URL permission. Tauri CSP denies object/frame embedding and restricts script execution to local scripts/WASM. |
| Import credentials | `crates/web/src/io/source_import.rs:16–42` sends an Addgene bearer token only after checking the exact `https://api.developers.addgene.org` origin, rejects redirects for credential-bearing direct requests and omits ambient browser credentials. The UI token signals are dialog memory, not local/session storage. Hosted/native gateway requests use binary requests rather than exposing provider download URLs as anchors or markup. |

## Scope limits

The review traced active markup sinks and the listed writers/links; it did not exhaustively prove all scientific operation outputs, imported SBOL graph semantics, provider networking, browser behavior, PDF parser behavior, native authorization or every storage path. SBOL documentary records were not found connected to the live raw HTML sink in this inspection. The PDF writer review did not identify a JavaScript/open-action/URI-action creation path, but this was not a general PDF-library audit. There was no runtime exploit execution or test validation in this worker.

Future changes that add raw markup, imported SVG rendering, citation sources or executable PDF actions require a fresh input-to-sink review; the negative evidence here only describes the inspected implementation.
