# Explicit lower-only Collagene XML compatibility profile

The original Java source was inspected read-only at `/tmp/collagene-original-audit`, commit `33f682a7156b875be730e18fa019ce310c9e54f6`. Its [writer](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/io/collagene/ExportOneXML.java#L25) serializes the two literal aligned rows. [AnnotatedSequence.setSequence](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/seq/AnnotatedSequence.java#L89) requires equal lengths but does not require an occupied upper row. [Sticky-part handling](https://github.com/mahogny/collagene/blob/33f682a7156b875be730e18fa019ce310c9e54f6/src/collagene/sequtil/LigationUtil.java#L85) also retains aligned absent cells. The existing migration already covers the other serialized sequence, annotation, color, primer and notes fields. No additional serialized operation graph, chemistry or history was found. No Java application code or scientific algorithm was copied or executed.

The missing case is a record whose upper row contains only spaces while the lower row contains actual calls. Ordinary migration has no upper reference and rejects the whole input. This remains the default; there is no silent strand switch or partial project recovery.

The new independent API is:

- `ReferencePolicy::{UpperOnly, AllowLowerOnly}` (serde and optional JSON Schema).
- `needs_lower_only_review(bytes) -> Result<bool, Error>` is a bounded review hint for recognized, well-formed containers/rows.
- `import_with_policy(bytes, policy) -> Result<ImportReport, Error>` returns all records atomically. `UpperOnly`, and ordinary files without a lower-only record, delegate unchanged to the existing importer.

`AllowLowerOnly` explicitly projects actual lower-row calls into a usable reference. The legacy lower row is displayed 3′→5′ from left to right. Therefore `ACGTTA` becomes the actual 5′→3′ call string `ATTGCA` by reversal, **not reverse complementation**. Missing upper cells are never filled. Space gaps outside a mapped footprint are omitted from the reference, but neither continuity across those gaps nor a covalent strand is established.

The adapter uses the existing legacy parser for record, primer, color, orientation and scalar validation through a bounded temporary lower-reference view. It then restores exact original project bytes/hash, original upper/lower rows and original record index for every returned record. The temporary view is never retained as original-source evidence. Ordinary siblings keep their existing sequence semantics. All lower-reference records carry restrictive `ss-DNA` and `source:legacy:chemistry_unmapped` metadata, preventing intact-duplex cloning assumptions or imported material authority. Unknown workflow evidence remains attached and explicitly uninterpreted.

Source coordinates remain zero-based half-open aligned-column intervals. An interval containing only actual lower residues can be mapped exactly through lower-row prefix counts into the reversed reference, including a declared circular-origin crossing. Original forward/reverse annotation directions are reversed as documentary coordinates; the original direction and aligned interval remain qualifiers. Unoriented features use `Order` and do not acquire a biological extraction direction. Footprints crossing absent lower cells, unsupported out-of-range/multiple-turn intervals, ambiguous equal endpoints and wrapped linear ranges remain unresolved and review-required. Literal primer oligos are retained without choosing a tail, domain or successful binding.

The profile enforces existing XML byte/node/depth/record/feature limits, disables DTDs, preflights the repeated full-source attachment size and bounds aggregate native output. Unknown project record types, invalid siblings or unsupported namespace-dependent record fragments fail the whole import. Synthetic tests cover default refusal and ordinary equivalence, mixed projects, literal lower reversal, exact reverse coordinates, circular wrapping, gaps/unoriented footprints, mismatching primer evidence, original-byte/native round trips, long XML attribute spacing/entities, unknown workflow and malformed/over-budget atomic failures. Real producer-generated lower-only interoperability remains unverified.
