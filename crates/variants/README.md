# collagene-variants

MIT Rust VCF4 / BCF2.2 exchange infrastructure. This crate parses declared variant-file evidence; it does not call variants, fetch a reference, interpret clinical significance, confirm coverage, or turn symbolic alleles/breakends into invented DNA. Browser and MCP hosts use a private completed collection; decoded reports cannot recreate it.

`Collection::import(bytes, Format, &Limits)` publishes only a complete private collection. `header()` and `record(index)` provide read-only Noodles typed INFO, FORMAT, sample, missing-value and genotype/phasing APIs. The header includes sample-column order and contig/field dictionaries as assertions. There is no mutable accessor or Deserialize authority. `page(offset, limit)` returns at most 100 normalized VCF rows with an aggregate 4 MiB text/name cap with explicitly 1-based declared positions; a missing/telomeric position stays absent. Full original lexical VCF or compressed BCF bytes and their BLAKE3 are always independently available.

`export(Original|Vcf|Bcf, max_bytes)` is atomic: failures return no output. Original is byte-exact. Canonical pages and normalized VCF exports replace empty sample columns emitted by the pinned lazy writer with the required missing marker (`.`), including when FORMAT itself is missing. This supplies no allele, ploidy or FORMAT value. VCF/BCF conversions produce a notice about normalization (header ordering/indexing, float/integer spelling and widths, missing/vector-end storage); a codec representation error is returned rather than silently dropping a field. Reference DNA, INFO/NM-like assertions and clinical validity are not inferred. Explicit formats are required: CRAM and BCF1 are unsupported. VCF accepts standard gzip (including concatenated members) with decoded bounds, CRC and full-consumption validation, or strict BGZF when its extra field declares BC. BCF accepts uncompressed BCF2.2 or strict BGZF with EOF; ordinary gzip BCF is rejected. No TBI/CSI/random access yet.

Limits are validated against hard ceilings before source copies: source <=64 MiB, decoded <=64 MiB, header <=4 MiB and 4096 lines, record <=1 MiB, records <=100,000, samples <=1024, conservative retained charge <=256 MiB. Defaults are smaller. The conservative charge reserves original + three decoded budgets + record slots + canonical-record scratch, so tighter source-specific profiles can reject even a small file rather than overpromise memory. BCF length/sample fields and VCF lines/column counts are checked before parser allocation. A quote-aware structured-header pass bounds actual INFO/FORMAT/FILTER/contig IDX slots (including conservative subsequent implicit entries) to 4096; quoted Description text is not treated as an index. All BCF typed extended counts, allele dimensions and sample-multiplied payload sizes are checked against actual raw bytes before the upstream raw indexer runs. Header/type consistency, UTF-8 and scalar sentinel checks guard known upstream lazy-sample panic branches. GT widths other than int8 and unsupported type combinations return explicit errors; no field is discarded. The BGZF encoder is consumed with `finish` exactly once so its destructor cannot append a second EOF marker. BCF conversion normalizes an entirely missing GT field to the literal missing allele (`.`) in a bounded temporary record; it never supplies a called allele or copies another sample’s ploidy. Explicit `./.` remains two missing alleles, and missing DP stays missing. The pinned encoder only supports GT allele indices through 62 (int8 encoding); larger indices return an error before integer encoding. Its mixed-ploidy padding is safe for equal lengths or a one-allele sample alongside a larger ploidy, but mixed nonhaploid lengths (for example diploid/triploid) are rejected before writing records. These are codec limits, not invalidity of the source VCF or inherent BCF restrictions. Original and normalized VCF remain available. The pinned BCF encoder cannot represent a present wholly missing INFO value safely, so that conversion returns an explicit error and Original/VCF remain available. BGZF framing, per-block ISIZE <=64 KiB, aggregate decoded bytes, deflate consumption, CRC and final EOF are verified before each decoded block is retained. The first host version stages bounded decoded BCF and raw records in memory; it never hands an unrestricted gzip stream to a decompressor. Future streaming/indexed hosts can replace staging without making collections mutable. This is managed resource policy, not an allocator-level OS sandbox.

No async, filesystem, networking, subprocess or native compression features. Noodles 0.87 VCF / 0.85 BCF (MIT), flate2 Rust backend, crc32fast and BLAKE3 are established standalone dependencies; no cloning application code or variant datasets were borrowed. Literal fixtures cover independent phased/missing multiallelic and breakend records, original bytes, cross-format exchange and bounded failure paths.

Primary format references: [official hts-specs VCF/BCF specifications](https://github.com/samtools/hts-specs), [Noodles VCF API](https://docs.rs/noodles-vcf/0.87.0/noodles_vcf/), [Noodles BCF API](https://docs.rs/noodles-bcf/0.85.0/noodles_bcf/). API and dependency licensing inspected in locally cached upstream source. Fixtures authored here; no external executable is required at runtime.

Native and WASM compiler checks for initial integration were coordinated by the parent agent. Follow-up conversion fixtures cover missing GT with explicit missing DP, phased multiallelic and haploid/diploid samples, and atomic rejection of known codec limits. Execution results are recorded separately from source-authored coverage. Browser/MCP host integration uses fixed bounded profiles.
