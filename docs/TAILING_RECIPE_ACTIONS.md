# Per-row TA/GC tail decisions

`tailing_recipe` is the public row-specific TA/GC recipe compiler. Each new row declares a normal original-source `FragmentSpec`, `Action::KeepExisting` or `Action::AddTail { base }`, and an optional explicit end treatment. `Profile::Ta` allows only new A/T tails; `Profile::Gc` allows only new G/C tails. No profile identifies a commercial enzyme or supplies terminal chemistry.

`KeepExisting` emits no `Tail3Prime` step. It uses the actual result of the declared preparation: for a saved tailed stock, the row must retain its exact `FromRun` or `FromDerived` source recipe. The compiler does not flatten the stock to an imported DNA input, remove restrictive markers, repeat upstream PCR as a new order, alter orientations or repair ends implicitly. The existing shared native origin ledger and preparation compiler retain original event bindings, tracked modifications and inherited incomplete evidence. Explicit `treatment` is a distinct requested operation, including on a held row.

`source_preflight`, `preflight`, `preview_revision`, `compile` and `preview` take independently declared source inputs and intended target. Source validation does not use that target to choose a source, tail or alternative. The compiler emits established operations followed by `ligation_outcomes::operation`, preserving the declared intended order/orientations. Larger supported ordered assemblies use the same operation and retain the intended product with explicit not-enumerated alternative-search status. Native verification supplies physical end eligibility, nicking, actual compatibility and the intended-product target check. Alternative orientation existence does not invalidate the compatible intended path; probabilities and isolation are not modeled.

The preview exposes both ordinary `verification.status` and a distinct `profile_status` (`Matched`, `Incompatible`, `Undetermined`) with explicit findings. A TA/GC profile matches only when the fresh native prepared prefix establishes one-base 3′ A/T or G/C ends on every row and complementary intended junction tails. Missing native geometry remains undetermined; blunt, wrong-family, circular-without-free-ends and incompatible tail geometry are not matched. Thus a generic all-blunt ligation can verify against its intended target while being explicitly incompatible with the TA/GC profile. Conversely matching tail geometry does not supply a missing 5′ phosphate or grant ligation success. UI integration must show both assessments and must not advertise a matched TA/GC workflow when the profile is incompatible/undetermined.

Rows retain the ordinary `PreparedRow` plus optional `tail_step`, optional `treatment_step` and the actual final `prepared_source`. Preview physical summaries come from the fresh native trace, before assembly orientation is applied for display; inputs use only the existing restrictive intact-reference assumption. No serialized summary is restored into material. `Preview::validate_binding(context)` reconstructs the declared preparation/action chain against the retained independent target revision without creating any target DNA. `Preview::validate_for(inputs, target, recipe, context)` additionally binds the caller’s exact source and target request. Both perform bounded documentary correspondence checks without scientific replay. Such validation is not physical authority; receiving adapters must additionally pin the private worker receipt and exact workspace/event epoch before presentation or installation.

Bounds reuse shared source/origin/model policies: at most 128 rows, at most 1000 emitted operations, shared 32 MiB origin and serialized recipe/report budgets, and existing prepared-role base limits. The recipe is stream-size-checked before cloning preparation strings or origin bytes; all roots/descendants share the established origin preflight. A report exceeding its full representation bound is refused explicitly, without silently dropping alternatives.

The sole core compiler is exposed through the existing worker job, MCP tool and GUI recipe workflow. Fixed and standalone GUI workflows share source rows, per-row keep/add actions and separate profile findings. Native model and SDK fixtures and the integrated web/worker WASM check pass. Tests declare literal TA/GC scar sequences, reconstruct an actual saved T-tailed vector before adding an A tail to a new insert, reuse two saved already-tailed stocks without new tailing/primer orders, check literal products for all four explicit bases, reject missing-phosphate compatibility and distinguish valid generic blunt ligation from an actual TA profile. Additional fixtures verify explicit reverse-orientation intent, refusal to target-select an alternative, and retention of a real reusable but incomplete homology→tailed-stock origin through downstream TA ligation. These tests establish native/model correspondence; graphical acceptance remains deferred, and kit activity or yields are not modeled.
