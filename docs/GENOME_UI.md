# Large genome references in the browser

The Genome references panel imports FASTA and `.cgref` files independently of ordinary sequence documents. A reference can exceed the 10-million-base Molecule limit and the ordinary web file limit. The browser reads source `Blob.slice` ranges of at most one MiB, writes immutable packed 65,536-base blocks to the separate `collagene-genomes` IndexedDB database, then reads those stored blocks through a fresh worker semantic validator. Publication of the manifest and catalog entry requires full canonical contig hashes and a still-present staging marker in the same publication transaction. Cancellation, quota failures, malformed data and readback errors remove the operation's unpublished namespace. A crashed tab may leave unpublished storage; global staging deletion is deliberately unavailable because another tab may still be importing.

Workspace archives contain validated `genome-reference-link-v1` descriptors, not bulk DNA. The local catalog is capped at 1,000 published datasets; remove cached data explicitly before adding another at capacity. Each link has a persistent logical role and pins both canonical content revision and the complete manifest hash. Cache hints only locate local data. Identical files under different roles do not share intended-locus identity. Missing data is shown explicitly; reattach an exact `.cgref` matching the retained descriptor. Reopening metadata restores no current semantic receipt or search authority.

The source interval uses 1-based inclusive input coordinates; a circular end may continue past the source origin for one traversal. At most 200,000 forward footprint owner starts are considered. Read windows carry typed global coordinates and remain bounded canvas views, never chromosome Molecule documents. Only visible sequence rows are painted when scrolling. Guide and hit navigation opens a verified local window in the result's original reference role without changing the active guide/search scope.

SpCas9 NGG and Cas12a TTTV profiles report DNA spacers, PAM positions, orientation and advisory nominal cut boundaries. A DNA spacer is not a complete guide RNA or scaffold. Search supports Hamming mismatches and IUPAC uncertainty, not bulges, nuclease efficiency or cellular editing. Explicit comparison, index and hit limits are visible. Each bounded worker request advances a private owner cursor; the complete operation may take longer than 30 seconds without a single long request. Cancellation destroys the cursor. JSON evidence cannot resume it.

Fresh whole-reference search must verify every owner block exactly once and finish canonical contig hashes. `exhaustive_for_manifest` means every imported contig was searched under the declared limits. `complete` additionally requires that the manifest's declared expected-component conditions hold. A plain FASTA with no expected list remains a declared collection: exhaustive collection search is not a whole-build absence claim. Assembly accessions, versions and provenance labels do not authenticate provider releases or population coverage. Intended sites are retained and flagged only for the exact role, hashes, contig, guide/PAM positions and orientation.

Native export verifies immutable block Blob snapshots and uses those same snapshots as the output parts, together with the pinned canonical manifest and footer. No full-reference DNA or packed file buffer is allocated. Keep the exported `.cgref` separately from the workspace archive. Guide and full retained hit evidence can be exported as bounded JSON; imports of serialized reports do not restore coverage authority.

Development validation: `scripts/genome_browser_qa.py` runs against a fresh compiled worker and local isolated Chrome, exercises a >32 MiB canonical FASTA, global seam/circular/reverse geometry, explicit-role identity, complete/incomplete coverage, native cache export/import, storage failures, archive descriptors, reload/reattachment, bounded rendering and desktop layout. It uses literal synthetic fixtures and an independent small sequence oracle; no scientific executable is called.

Mobile design and acceptance are deferred until the desktop product is finished and the user has reviewed and edited it. Current validation and delivery gates concern the desktop workflow.
