# Shared server source imports

The Rust shared-library server mounts `POST /api/source-import/v1` on its existing listener. Requests use the source gateway's CGSQ version 1 binary envelope and `application/vnd.collagene.source+postcard`; replies use its bounded CGSR envelope. The library v1 and reliable-sync routes retain their existing binary formats and media types.

Every source request requires the same lab bearer key, exact configured Host, and matching Origin when present. `X-Collagene-Expected-Lab` is required and must match the trusted startup lab. Authentication and origin checks precede the lab assertion; all precede reading or polling the body. Missing, wrong, and duplicate lab assertions return 428, 412, and 400 respectively. The assertion never selects a lab or grants access. Request bodies are limited to 16 KiB including framing (or the configured smaller server body limit), and source replies to 64 MiB including framing. Unsupported media, ambiguous encoding/length headers, URI authority/query components, and malformed frames are rejected.

The server calls `collagene_source_gateway::Gateway<NativeBackend>::execute` as a trusted owning host. No second gateway listener is started. The gateway preserves its client-session nonce scoping for cancellation and reviewed Addgene catalogs. Provider access continues through `collagene-sources`: approved URLs, authentication, redirects, catalog selections, parsing bounds, and provenance are enforced there. This route is not a generic URL proxy, upload directory, filesystem interface, or executable launcher. Provider credentials remain request-only and are never included in returned catalog summaries, logs, or static assets. Public deployments require the existing TLS reverse-proxy arrangement for both lab and provider credentials.

Four separate source ingress slots bound small request bodies and parsing. Authenticated Cancel/Dispose operations bypass occupied provider/large-response admission and retain their ingress slot through a response bounded to 4 KiB. Ordinary source work releases its ingress slot only after acquiring the shared heavy lease. Source work shares the server's bounded admission with library/sync requests. The gateway separately retains native provider admission while already-running bounded parser work finishes. Aborting an in-process request future cancels its provider future and clears its active nonce entry; the gateway enforces its provider deadline, with an additional 90-second owning-host deadline. Encoded reply bytes retain the shared admission lease through all outgoing frame clones and slices, including after the response body itself is dropped. Source encoding runs off the async executor and retains admission if its caller disappears.

The immutable in-memory index snapshot contains exactly one canonical enabled marker for each of `collagene-library` and `collagene-source-gateway`. Duplicate, conflicting, or misplaced active markers reject startup. Existing valid markers are handled idempotently; comments and raw script text do not count as active markers. Original disk files and referenced JS/WASM/integrity attributes are unchanged. The separate static preview server does not advertise these capabilities. Browser source imports use the connected library session key and expected-lab assertion; credentials are not embedded in the capability markers.

`ServerState::new` selects the real native backend. `ServerState::with_source_backend` accepts an injected native `Backend` only at trusted construction time for in-process router fixtures. Fixtures exercise rejection before body polling, namespace isolation and bounded bodies, real gateway dispatch with a fake provider, shared reply-frame admission, cleanup/reuse after caller cancellation, and explicit Cancel/Dispose delivery while a single heavy slot is occupied. They do not create listeners, call providers, launch browsers, or access a credential vault. Live provider interoperability remains separate from these router checks.
