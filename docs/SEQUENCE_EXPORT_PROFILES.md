# Reviewed sequence-file export profiles

`sequence_export` is the UI-independent facade for the current selected SnapGene, XDNA v0 and Wisconsin/GCG single-sequence writers. It does not import files, run scientific reconstruction, select filesystem paths or persist exports. Existing native archive/original-source downloads remain separate.

The explicit `Format` is `SnapGene`, `Xdna` or `Gcg { options: gcg_sequence::ExportOptions }`. `revision(molecule, format)` checks bounded rich source models, restrictive chemistry evidence and structural format/options before streaming the full native source revision into a context hash. The context includes the facade engine, scientific engine, exact source revision and all explicit format options. Dates and GCG record IDs are supplied explicitly or taken from the existing writer’s retained documentary metadata; no clock, placeholder or inferred alphabet is introduced.

`review` returns an `Assessment` containing `engine_version`, `context_revision`, `source_revision`, selected `profile`, portable suggested `filename`, `mime`, typed `losses { path, message }` and advisory `warnings`. SnapGene/XDNA retain their writer loss inventories. Every existing GCG writer warning becomes a typed loss as well, preserving the previous UI’s acknowledgement requirement for its sequence-only projection, omitted annotations/metadata/originals, circular topology and RNA/DNA type ambiguity. A different embedded GCG record ID also reports loss of the native display name.

`prepare(molecule, format, expected_context_revision, allow_omissions)` rejects a stale source or option change before generating an artifact. It reruns the actual writer, carries the same deterministic assessment and refuses any nonempty loss inventory unless explicitly acknowledged. `Prepared { assessment, bytes }` is a bounded data artifact; preparing bytes is not a successful file save. Hosts must recheck their source/event/epoch after worker admission and await their native export acknowledgement before showing success.

Both reply DTOs expose readonly `validate_binding(expected_context_revision)`. These check bounded text/collections, lowercase revision digests, known profile, consistent MIME/extension and a safe basename. Prepared replies additionally require nonempty bytes at most 32 MiB and a matching container signature. These documentary guards do not restore physical material or establish full scientific verification. Hosts still bind the returned assessment to the immutable captured request and compare the preparation assessment with the reviewed assessment.

Portable filenames retain the native display name when usable. Unsafe characters are replaced, Windows reserved basenames are prefixed, and empty or oversized names use a stable source-hash basename; any change appears in warnings and never edits the native document name. Filename suggestions convey no directory authority. XDNA’s missing embedded-name field remains an explicit writer loss even when a suggested filename is available.

The facade preserves each writer’s restrictive-evidence checks. Known physical, modified, damaged, declared-terminus, single/mixed-strand and reference-only sources cannot be turned into clean sequence references through `allow_omissions`. Protein modification evidence and unmapped XDNA overhangs retain their existing refusals. Supported field/coordinate/alphabet limits remain those of each selected writer; the shared 32 MiB ceiling does not widen a narrower GCG or model limit.

`review` does not return file bytes. GCG currently performs its bounded textual writer during review and discards that text; this is documentary formatting, not an independent scientific computation. These functions belong in analysis workers, rather than synchronous UI handlers.

Six focused fixture groups cover matching review/preparation assessments, current-source and option staleness, explicit XDNA/GCG acknowledgement, chemistry refusals, safe filenames/reply shapes and actual worker jobs 174/175 with result selectors 164/165 under worker schema 90. They retain old-header refusals and demonstrate that advisory SnapGene scope warnings alone do not invent an omission.

Integration requires registering `pub mod sequence_export` in `core/src/lib.rs`. Protocol and frontend adapters are maintained by the parent integration work; this module has no UI or native-file dependencies.
