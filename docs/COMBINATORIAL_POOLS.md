# Per-construct Golden Gate reaction choices

The source matrix now connects to the existing finite Golden Gate reaction model.
Each construct can supply prepared material, a whole original source or a complete
exact-PCR amplicon before digestion. Whole substrates retain every digest piece
and separate circular carryover; target-contribution intervals never trim the
material entering the reaction. Raw fields remain editable per construct.

## Discovery, intent and checking

Enable finite-pool settings for a Golden Gate construct, choose its substrates
and search limits, then inspect that construct's reaction. Native resolution uses
the stable design/construct/bin/choice identities and exact retained source events.
Discovery accepts a missing candidate choice; compilation does not. The index-zero
probe collects preparation and enumeration evidence and never selects a winner.

Review all returned candidates, independent-target comparisons, raw fragment
paths, duplex geometry, terminal chemistry and recognition/recut observations.
Separate pages retain search warnings, missing/preparation findings, assumptions,
fragments, nicks and circular carryover. The sequence canvas is a read-only
top-strand reference; it does not replace physical evidence. Complete discovery
JSON is an explicit, guarded, bounded download.

**Use this candidate for this construct** saves only a declaration: inspection
context, candidate index, directed sequence key, physical sequence key and an
outer source-intent revision. The latter binds exact input events, contribution
coordinates/orientation, stable source-choice identity, independent target
declaration and complete reaction request. Equal DNA in another event does not
inherit the earlier choice. No imported report or saved positive status supplies
fresh authority.

The new typed `SelectedGoldenGate` operation carries the index and both keys.
Fresh verification enumerates once and checks those keys before accepting the
selected product. It independently checks the separately declared target. A
different target-matching product is never substituted. Wrong keys, unavailable
indices and recuttable products fail explicitly. Incomplete search retains its
existing limitations and requires the normal explicit incomplete-output policy.

The selected reaction also opens the shared single-construct product/junction
review and output chooser directly. Ordered-method computation cannot silently
replace a source-matrix pool choice: the ordinary panel keeps preparation and pool
settings available but routes actual discovery/review through the construct panel.
Returning to ordered prepared assembly is an explicit action.

Batch evaluation and atomic release use the shared compilers and finalizer.
Compilation validates source consent and context without scientific enumeration;
the verifier performs the actual reconstruction. HTML/PDF instructions retain
the exact selected keys and source/preparation steps. Historical manifests and
fresh protocol export retain the same declaration checks.

## Editable state and transport

Draft version3 stores bounded candidate intent with each construct's pool settings.
Versions1/2 migrate without acquiring a choice or scientific evidence. The new
attachment kind is `assembly-draft-v14`; kind/version mismatches and duplicate active
drafts fail. Source/geometry/order changes invalidate selection where appropriate.
Clearing a choice keeps the pool draft; returning to ordered prepared assembly
explicitly clears the pool mode. Result filters preserve original construct IDs
and distinguish uncomputed drafts, reconstruction errors and evaluated statuses.

Worker59, candidate12, workspace plan10 and science15 isolate the appended operation
(ordinal18). Earlier ordinary operation and method selectors retain their layout.
Older labels reject the new operation and nested pool methods, including per-row
overrides; genuine older index-only Golden Gate data remains readable. Historical
run records do not become current verification on load.

MCP `inspect_combinatorial_pool` accepts an immutable workspace/design/construct,
returns source consent and candidate identities, and exposes the full discovery
artifact. A caller explicitly supplies its chosen pin before batch evaluation or
output release. The registry contains147 tools. No runtime scientific subprocess
or arbitrary filesystem access is introduced.

## Boundaries

This reuses the existing complete-cleavage, finite one-copy/orientation model.
It does not establish cycling kinetics, partial cleavage, repeated-copy
stoichiometry, methylation clearance or experimental yield. Whole amplicons use
the supported exact-PCR preparation; incompatible/mismatched preparation requests
remain explicit errors. Retained-nick pool products and silently discarded
terminal treatments are rejected. Further method coverage, optimization and
domestication, recovery retention management and final application acceptance
remain in scope. Reviewed library editing/recovery is now implemented
([details](ASSEMBLY_LIBRARY_EDITS.md)).
