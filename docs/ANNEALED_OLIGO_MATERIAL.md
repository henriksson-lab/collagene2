# Reusable annealed-oligo material

The DNA ends panel can review and retain an annealed adapter without creating an
assembly target. Both inputs must be explicitly declared independently supplied,
standard unmodified single-strand DNA oligos. Their 5′ and 3′ groups and the
annealing search bounds are separate declarations. Saved duplex material cannot
be implicitly denatured or flattened into a supplied oligo.

Native `material_derivation::Request` has one `sources` list of `BoundSource`
rows. Each row contains a `SourceRole`, an exact document/event/revision binding,
and its origin. Existing processing methods require exactly the `Template` role.
`AnnealedOligos` requires `TopOligo`, followed by `BottomOligo`. The JSON role names
are `template`, `top_oligo` and `bottom_oligo`.

Distinct roles may refer to the same self-complementary oligo event. History
parents deduplicate exact event identities, while the request, receipt and capsule
retain both role uses. This is not an identity-by-sequence lookup. Each source
must match its complete retained snapshot; equal letters with another event or
changed metadata do not replace the selected source.

The preview context binds both ordered role/event rows and all annealing options.
Selection retains the stable native candidate ID and exact preview/product
revisions. A candidate document and its serialized duplex summary are documentary;
installation independently reruns native annealing on the exact sources.

Execution reuses native antiparallel pairing enumeration, annotation projection
and `TrackedDuplex::annealed_unmodified`. Selecting a candidate does not establish
that it is the only reaction product, experimentally isolated or covalently
sealed. Alternative geometries and capped-search limitations remain incomplete
through installation and archive restart. Later cloning independently verifies its
intended target and may produce additional alternative products.

Original oligo annotations map to the actual selected strands. Native physical,
modified or reference-only producer markers are rejected even when a detached
preview's duplex summary has been removed. Explicit ssDNA labels are retained;
no metadata stripping is used to invent a duplex assumption.

Records and capsules use only schema2 and the current material attachment kind
and header. Capsules contain complete role-bound source snapshots. The existing
mixed ancestry ledger charges all snapshots and saved descendants before copying
or decoding deeper material. Source closure, TOPO graph bindings and selected
sharing retain both source histories while omitting unrelated private documents
and later private heads. No previous internal schema is decoded or migrated.

The existing generic installation transaction checks the complete source-role
receipt and current workspace/epoch before applying an archive. The web review
also pins both source events, both snapshots, explicit ssDNA declaration, termini
and search settings. Changing either source or settings requires a new review.
MCP uses the same native operation and returns a new immutable session workspace.
No new primer order is generated by annealing; supplied oligos remain source
provenance.

The internal stamps are worker113, candidate31, native plan29, editor draft19 and
science32. The integrated batch passes239 distinct native, SDK, worker and UI-model cases
and the web/worker WASM check. Cross-platform CI is tracked in
[implementation status](IMPLEMENTATION_STATUS.md). GUI and experimental
acceptance remain separate from these scientific and compiler results.
